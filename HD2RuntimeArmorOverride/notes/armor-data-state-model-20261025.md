# 护甲注册表数据的实体关系与不变式（2026-10-25）

发布前的安全基线。任何改动都必须让下面的不变式继续成立。

## 1. 实体

| 代号 | 是什么 | 位置 |
|---|---|---|
| **R** | 游戏目录里的注册表文件（会被真映射改写） | `data/game/generated_customization_armor_sets.dl_bin` |
| **B** | 原始备份，R 还是官方版时的**逐字节拷贝** | `<注册表根>/backup/generated_customization_armor_sets.original.dl_bin` |
| **S** | 状态文件 `pristineSha\|writtenSha\|pristineContent\|buildId` | `<注册表根>/backup/armor-data-mapping.state` |
| **I** | 资产索引（件表 + `source_fingerprint`） | 管理器数据库 |
| **P** | 协议 = 用户意图（目标→来源、素体定义） | `armor-registry.protocol` / 工作区 |
| **L** | 编译产物 = 运行时执行的 unit 对 | `wardrobe.links` |
| **M** | 映射模式 | 设置页 |

## 2. 不变式

| 编号 | 内容 | 由谁保证 |
|---|---|---|
| **I1** | 管理器看到的"权威数据"**永远是官方数据**——即使 R 被我们改过 | `ArmorDataFileIdentity.GetUnmodifiedSealedPath` 把 `encryptedPath` 换成 B |
| **I2** | 索引指纹对"我们写没写过 R"不敏感 | 身份 = `SHA256(B)`，而 B 就是原件，与 `SHA256(R原版)` 相等 |
| **I3** | B 必须是**当前游戏版本**的官方文件拷贝 | buildid 判据 + "文件既非 B 也非我们写的就重播" |
| **I4** | 非真映射模式下 R 必须是官方文件 | 应用/部署时走还原路径 |
| **I5** | 真映射的结果必须能由 `B + P` 完全重建 | 每次都从 B 重建，不做增量修改 |

## 3. 状态转移

| 操作 | R | B | S | I | L |
|---|---|---|---|---|---|
| **应用映射（真映射）** | ← `f(B,P)` | 必要时重播 | 更新 written | 不变（I1） | 不生成 |
| **应用映射（兼容模式）** | ← B（若曾被改） | 不变 | written=pristine | 不变 | ← 由 `权威(B)+P` 编译 |
| **切换模式 真→兼容** | ← B（部署时还原） | 不变 | 同上 | 不变 | 重新编译 |
| **关闭映射开关** | ← B | 不变 | 同上 | 不变 | 补丁移出计划 |
| **重建资产索引** | 不变 | 不变 | 不变 | ← 读 B（I1） | 不变 |
| **Steam 校验完整性** | ← 官方（Steam 写） | **删除** | **删除** | 下次检测时按 R 比对 | 不变 |
| **游戏更新** | ← 新官方（Steam 写） | 下次应用时重播 | 下次应用时更新 | 指纹变 → 提示重建 ✓ | 不变 |

## 4. 危险场景与防护

| 场景 | 若处理不当的后果 | 现状 |
|---|---|---|
| **在真映射状态下重建索引** | 索引记录"目标甲已持有来源甲的件"；切回兼容模式时 link 编译判定"无需映射"→ 映射静默失效 | ✅ 已修：权威一律读 B（I1） |
| **指纹按状态切换形态** | 每应用一次真映射索引必然误报过期 | ✅ 已修：身份恒为 `SHA256(B)`（I2） |
| **Steam 校验未完成就清基准** | 丢掉唯一的原件副本，下次把被改文件当原版 | ✅ 已修：只在后台探测确认完成后清 |
| **备份属于旧游戏版本** | 用旧版原件覆盖新版 R | ✅ 已修：buildid 判据 + 外部替换判据 |
| **状态文件丢失但备份在** | 继续信任来历不明的备份 | ✅ 已修：按当前 R 重播 |
| **状态说"是我们的"但备份丢了** | 把被改过的文件当原版，永久污染 | ✅ 已修：拒绝播种并提示先做 Steam 校验 |
| **手动删除 `backup/` 文件夹** | 同上一行 | ⚠️ 有防护但会中断真映射，**文档应提示不要手删** |

## 5. 兜底链条

```
出任何问题
   └─ Steam 校验完整性
        ├─ Steam 把 R 恢复成官方版本
        ├─ 清掉 B 和 S
        └─ 下次应用以恢复后的官方文件重新播种
             └─ 一切回到干净状态
```

这条链**不依赖任何我们自己的状态**，所以无论中间被改成什么样都能恢复。

## 6. 验收清单（发布前必做）

1. 真映射模式下**重建索引** → 索引件表仍为官方数据
2. 应用真映射 → 检测索引状态 → **不报过期**
3. 切到兼容模式 → link 编译正常（不是"目标已等于来源"）
4. 关掉映射开关 → R 恢复成官方哈希
5. Steam 校验 → R 回到官方哈希、B/S 被清、可重新应用
6. 游戏更新后 → 提示重建索引、真映射自动以新版本重播备份

第 1、2、3 条是这次改动的直接目标；第 4、5 条是撤销路径；第 6 条无法主动构造，靠 buildid 判据兜住。
