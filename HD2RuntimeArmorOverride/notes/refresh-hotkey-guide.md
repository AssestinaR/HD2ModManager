# 快捷键瞬时换装采样

## 使用

新版运行时已通过 CLI 部署。启动游戏并进入舰船后，双击：
`E:\Data\source\repos\WpfApp1\HD2RuntimeArmorOverride\scripts\Start-ArmorRefreshHotkey.cmd`

- 默认 F8 全局标记，F11 结束。前台PID仅作为诊断记录，不阻止采样。
  工具运行时不要在其他程序里使用F8，以免产生无关标记。
- 等待控制台“已就绪”和高音，然后操作；初始化通常需几秒。
- 在军械库中同步按 F8 和确认装备按钮。
- 大约半秒后，高音表示窗口有效，低音表示无效。声音有少量通信/处理延迟。
- 提示完成后再按下一次，不必切回窗口输入备注。默认8次后自动结束。
- 前2次仅按F8不换装，作为背景对照；随后4次在A/B间换装，
  最后2次换到结构明显不同的C。发回结果目录时简单说明A/B/C名称即可。
- 不切换身形、头盔、场景，不重新部署或应用映射。不必反复关闭军械库。
- 键位冲突可使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Data\source\repos\WpfApp1\HD2RuntimeArmorOverride\scripts\Watch-ArmorRefreshHotkey.ps1" -Key F9
```

## 记录与边界

外部工具使用RegisterHotKey消息，不装键盘钩子，不向游戏发送输入。
QPC频率需与Lua一致，记录消息队列延迟、工具处理标记时刻及Lua接收时刻。
标记是“用户即将确认”的参考，不等同于游戏接受换装的事件。

Lua先通过既有World/Unit只读接口找avatar候选，记录其数字句柄；
之后每帧重新验证句柄代次、对象/World身份和子节点链，
不持有跨帧engine userdata，不每帧遍历World列表，不跨会话保留代码缓存。
最多保留2秒/1024条标量观察，保存标记前后各0.5秒。
代码只读验证结果在这次诊断会话内复用，不重复采集机器码。

本版捕捉的是**高频装配子链变化**，没有原生调用栈，也没有把所有子节点
映射到资源ID（日志 resources_resolved=false）；不应把14个变化节点
全部称为护甲或声称已找到重建函数。本地玩家权限仍待验证。

无效条件包括：两端时钟频率不符、传输延迟超过150ms、
消息排队超过100ms、样本间隔超过100ms、前后数据不足、
对象身份/代次变化、注册revision变化。任一侧不足3个样本也无效。
身份变化后停止，不自动改追其他玩家。
单次检查耗时超过10ms则停止后续检查；无法抢占当前原生读取。
最大会话5分钟/30个标记；关闭工具正常退出时发送停止请求，
异常退出也不会无限采样。

F11、进程退出、错误、超时都会退出工具并释放快捷键和诊断锁。
不要同时运行旧采样向导。

## Lua深度版V2（资源身份观察）

现在要求 hotkey_version=2，增加独立、有界的资源关联批次：
从候选World重新获取合法Unit句柄，重新解析代次与对象，匹配当前/近期子节点，
调用已有name_hash/to_hex只读接口，并在读取后再次验证身份。
不将原生指针转换为引擎userdata。每批最多24个Unit、软预算0.5ms；
耗时超过5ms或失败会禁用资源批次，但保留主链观察及明确降级状态。

关联作为单独resource_identity记录输出，包含观测QPC、资源ID、对象、
句柄index/generation。不把历史地址关联无条件贴到每个帧上，
所以窗口头 resources_resolved=false 仍表示没有保证全量、同时解析完成。
资源证据可覆盖窗口之前额外2秒，用于保留已移出节点的最后身份；
它们不是同步快照，不能证明移出即销毁。头部resource_capture说明有无降级。

静置合成自检：
`../evidence/refresh-hotkey/20260926-150811-510f2808552e46f886bc6d79095c435a`。
143帧、34条身份观察、17/18个不同子对象获得资源ID，
资源批次最大0.6014ms，帧间隔最大11.2064ms。
这是静置测试，不是换装压力测试；旧版8窗仍保留，不需重复完整矩阵。
建议新版本先做1次静置＋2次不同护甲切换，观察资源关联覆盖。

## Lua深度版V3（组件时间序列，历史）

用户确认全部护甲映射同一自定义素体，故资源相同是有意的控制变量，
不能当作映射异常；有利于比较不同装备触发同一外观装配的变化。

V3保留一秒主窗口，新增对证据派生的0x124组件固定0xc30字节区域的
只读、双读一致性检查；记录32个0x58步长记录的两个原始字段、
游标、变化dword偏移以及与avatar/近期子节点地址的精确相等关系。
这些字段不是已证明的Unit句柄，也不证明0x124属于护甲。
只读已验证指纹模块中的固定列表，最多256项且必须唯一匹配；
没有全堆扫描、未知函数调用、内存写入。组件读耗时超2ms禁用后续组件采样。
每约10ms可检查一次，实际受游戏update限制。没有变化不能排除帧间短暂活动。

资源扫描观察到成员列表变化后优先从尾部512项开始、随后遍历其余部分，
不假定新增Unit只能在尾部；修复count变化导致反复重置游标的问题。
主窗口不扩展，但保存完成延至标记后约1.25秒（额外0.75秒补资源身份）。
请听完成提示再做下一次；建议本轮1次静置＋2次不同护甲换装。
