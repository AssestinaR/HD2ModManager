## 二、你只需要测这一次（约 15 分钟）

### 1. 组编辑器（不用进游戏）

打开任意有 `components.json` 的 Mod → 详情页「衣物装饰组件」卡：

| 动作 | 期望 |
|---|---|
| 看组列表 | 名字、`N 块 · 来自源侧开关包`、勾选框都在 |
| 改一个组名，点别处，**切到别的 Mod 再回来** | 名字还在 |
| 勾掉一个组 | 树上对应的节跟着变灰 |
| **勾完立刻切走再回来** | 勾选还在（这是这次修的老毛病） |
| 树里选一块几何 → 填名字 → 「新建组」 | 新组出现，块数对得上 |
| 删一个组 | 组消失，**几何还在** |
| 重启管理器 | 以上改动全部还在 |

### 2. 就地烘焙（不用进游戏，但看耗时）

同一个 Mod 点「应用」：

| 期望 |
|---|
| **几秒内完成**（以前几分钟） |
| 状态栏说"已烘焙：关掉 N 个 section…" |
| 再点一次 → "已经是目标状态，没有写入任何字节"（幂等） |
| 把组勾回来再点 → "打开 N 个 section"，产物恢复 |

> 前提：该 Mod 得先换过一次目标护甲（有 `Overwrite/`）。否则会退回重跑换甲，那是正常的。

### 3. 实机最小版（只有这一条必须进游戏）

按 `sectional-v0-verification-20261104.md` §2：

1. 挑一件熟悉的护甲，装一个 Mod，进游戏
2. 关掉一个组 → 那块几何应消失
3. 勾回来 → 应回来
4. 勾另一个组 → 前一个应自动关掉（互斥组）

### 4. 顺手验一下装饰退场没伤到选项（关键）

因为「装饰」与「选项」共用了宿主附加面板，这一条必须看：

| 动作 | 期望 |
|---|---|
| 随表打开一个**有选项**的宿主 Mod | 详情页底部出现「可为该 Mod 启用的附加选项」列表 |
| 在列表里点某个选项的启用按钮 | 选项被启用，列表状态跟着变 |
| 打开库页 | 顶部**没有**「显示装饰 / 隐藏装饰」这颗按钮了 |
| 拖一个 Mod 到宿主上设为其选项 | 正常生效 |

## 八、合并后仍存在的风险与明示的技术债

1. **`lunalice_bill` 的载荷丢了**（状态文档文末）。与本分支无关，但那 12 个 option 挂在空宿主上。
2. **拆件的 donor 合并没有实机证据**。V0 离线三条已过，实机三条待你。
3. **`uniqueSlotPerSection` 的代价**：材质槽与 `BoneInfo.Remaps` 条数随段数线性增长；
   100+ 段是否可行**没测过**。
4. **`ModEntity.IsDecoration` 属性保留**（恒为 false），全仓还有 44 处 `!mod.IsDecoration` 之类的
   守卫。删它要动 17 个文件、全是 UI 判断——收益是"少 44 行"，风险是"看起来编译过但行为变了"。
   判断是不值当，**已记为明示技术债**，不是漏删。
5. **`DecorationHost:` 作用域与 `IsHostDecorationSelected` 等命名保留**：它们服务**选项**
   宿主面板（库里 121 个选项靠它），只是历史命名。改名要波及 XAML 绑定，收益不值风险。
6. **`decoration-activations.json` 这份旧文件不再被读写**，但 `StoragePaths.DecorationActivationsPath`
   路径常量留着（将来要清理残留时用得上）。
