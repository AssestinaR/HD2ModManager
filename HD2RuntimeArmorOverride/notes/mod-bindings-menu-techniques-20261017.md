# 从 `Mod Bindings Menu v2.2` 学到的技术栈（2026-10-17）

用户提供：`C:\Users\Administrator\Downloads\Mod Bindings Menu 16478 2.2 ...zip`。
这是一个给 mod 提供设置页面的 addon，能在运行中给游戏加一个原生 MODS 标签页。

## 包结构（和我们构建的 addon 同构）

```
manifest.json                       { Version, Guid, Name, IconPath, Description, Options[{Include:["Addon"]}] }
INSTALL.txt
thumbnail.png
Addon/9ba626afa44a3aa3.patch_0      52,912 B   ← input / UI 资源（input_type、SelectHeaderTab1..8 …）
Addon/9ba626afa44a3aa3.patch_1     132,624 B   ← Lua，**明文未压缩**
```

**关键：`patch_1` 里的 Lua 是明文。** 开头就是
`-- HD2-Addon: mods/cowboybingus/mod_bindings_menu` / `-- Generated by scripts/build.py from ...`。
所以 `build_addon.py` 产出的 zip 形状是对的，只是还缺"管理器导入"这一步。

## 内存访问方式（可直接复用）

不用 `ffi.load`，而是用 **`__asm__` 别名**把 kernel32 导出绑到自定义名字上：

```lua
ffi.cdef[[
void *bingus_memory1_GetModuleHandleA(const char *name) __asm__("GetModuleHandleA");
int   bingus_memory1_ReadProcessMemory(void *process, const void *address,
        void *buffer, size_t size, size_t *done) __asm__("ReadProcessMemory");
]]
local kernel32 = {'GetModuleHandleA','GetModuleFileNameW','GetCurrentProcess',
                  'ReadProcessMemory','VirtualQuery', ...}
```

配合 `GetCurrentProcess()` + `ReadProcessMemory` 读**自己的**进程，
再按 **`game.dll + 硬编码 RVA`** 取数据：

```lua
M.GAME = {settings = 0x3326340, index = 705500 + 212, table = 0x37C5650, count = 15}
```

它还顺便用 `bcrypt` 对模块文件算 SHA256 做版本指纹 —— 也就是**按构建号校验偏移**，
这和我们 `notes/` 里"游戏更新就失效"的担心是同一个问题的成熟解法。

## 它**没有**做的事（这才是重点）

* 没有 `VirtualProtect`
* 没有写 `game.dll` 代码段
* UI 不是运行时 hack，而是**替换 input/UI 资源资产**（`input_type`、`SelectHeaderTabN`）

## 因此反作弊的边界可以精确表述

| 行为 | 是否可用 | 依据 |
|---|---|---|
| 读游戏内存（`ReadProcessMemory` 自己进程） | ✅ | 本 mod 大量使用 |
| 写游戏**数据**（注册表 blob、协议） | ✅ | 我们的运行时一直在做 |
| 替换**资源资产**（patch 归档里的 input/UI/unit） | ✅ | 本 mod 的做法 |
| 改**代码段**（`VirtualProtect` + 写） | ❌ | 两次实测被判定「可疑程序」 |

## 对扩容的意义

扩容要么来自**更多槽位/更多 bank**（那是代码，❌），要么来自**资源层能表达更多部件**
（✅，待查）。

值得查的资源：`data/game/generated_unit_customization_settings.dl_bin`（27,792 B）、
`generated_body_settings.dl_bin`、`generated_customization_armor_sets.dl_bin`。
初步看它们都是二进制/哈希格式，没有可读的 `slot`/`bank`/`limit` 字样，
需要走 `hd2mod gamedata` 的类型化解析才能看出结构。
