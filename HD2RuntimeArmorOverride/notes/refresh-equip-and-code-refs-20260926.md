### 结论与边界

- 静置没有变化；两次换装都保持 avatar 观察键，而替换 14 个子链成员。
  这不是仅列表重排，是具体装配关联的成员替换。
- 不能把 14 个全部称为护甲 Unit：本轮没有对子对象做资源身份采样。
  旧证据曾匹配 12 个护甲资源，但不能跨进程复用资源/指针对应关系。
- 指针退出列表不证明对象已销毁；generation/地址相同不排除 ABA。
- 仍未证明多人本地玩家权限，也未取得上层外观重建入口。
- 更支持调查“在保留 avatar 的情况下替换视觉装配”，不支持直接
  销毁角色、改游戏装备或调用通用 link 来假装重建。

## V10 自动只读代码引用调查

新增 `src/armor_refresh_code_probe.lua`，仅请求 code_refs 时运行。
两模块指纹固定，PE64 可执行 section 按每 tick 64KiB 分块读取。
最大 64 个命中，每个 exception-directory range 最多捕获 16KiB。
request 不接受地址。没有函数执行、Hook、修改页保护或附加调试器。
新增 Core 嵌入资源、独立生成器支持、离线 Capstone 分析脚本。

`evidence/refresh/20260926-133854-93e9c976a5004c5f9d57197d1134c67a`

第二轮：
`evidence/refresh/20260926-134236-b58f941f70d242e7a0acfaf9d15dee5d`

阶段 complete、无截断，未找到新增 game.dll 调用点。
这是分帧总耗时，不是单帧耗时或完整端到端性能保证。

0x12ea65 所在范围根据 `record+0x50` 类型跳转，记录步长 0x58，
记录区域基址 +0x10038，与先前捕获的 0x3362c0 / 0x336310 入队写入
布局吻合，支持“通用命令队列消费者”的解释。
**没有观察它在换装时执行**，不能命名为装备/刷新专用控制器。

重要：PE exception table range 有些是 chained range / funclet；
例如 0x12ea65、0x3aac8c 不是独立函数入口的已知证据。
不能按 range begin 构造可调用指针。解码验证不是调用 ABI 验证。
当前调查不覆盖寄存器调用、虚表调用、间接多级 thunk、内联实现，
故没有 game.dll 命中不意味着游戏逻辑不使用这些路径。

## 下一步：不要求用户重复相同换装实验

1. 转向有限的接口表/虚表引用关系，找 game.dll 如何引用已确认的
   同步或排队挂接函数。不要再扩大同一种 E8 搜索。
2. 先只读调查模块内对目标函数的指针引用，再离线复核表结构和其
   消费位置；每层应记录“观察到什么”和“尚未证明什么”。
3. 真正值得追加人工采样时，应是已经找到候选上层控制器，
   需要验证它与这 14 个变化成员的对应，而非再确认子链会变。
4. 生产自动刷新继续关闭；没有线程、生命周期、身份与参数保证前
   不调用队列消费者，不直接改队列、link/unlink 或 spawn/destroy。
