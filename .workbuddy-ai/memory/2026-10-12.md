### 决定性发现：**前倾只存在于绑定姿态（bind pose），游戏从不显示这一帧**

- 游戏运行时算的是 `A[b] · inv(R[b]) · v`（A = 当前动画骨骼，R = 我们发布的静止骨架）。
  站着不动时 `A` = HD2 自己的静止骨架 ⇒ **游戏显示的是"用 HD2 站姿重摆过"的那一帧**。
- 上一轮的截图（"batch 风格"那列）画的是**绑定姿态**（`out`），所以看起来前倾。
- 把游戏那一帧算出来渲染（`out_idle`，见 `out/final-compare.png` 第 3 列）：**是直的**，
  站姿与参照 patch（第 4 列）接近。

**为什么我们的绑定姿态会前倾：管线少做了 BatchTool 的最后一步「转回初态 + 原始骨轴」。**
那一步把骨架**还原成 HD2 自己的静止骨架**，而此前"HD2 骨的 head := 源映射骨的世界位置"
造成的网格形变**被烘焙进网格**。⇒ BatchTool / 参照 patch 最终发布的是
**骨架 = HD2 原生静止骨架（逐位一致）+ 网格 = 烘焙后的、已经长成 HD2 站姿的网格**。
`out_idle` 就是那个烘焙后的网格。

旧 `skeleton='snap'`（把 HD2 关节吸附到源关节）⇒ `S_bind ≠ rest_hd2` ⇒ 每帧被 `rest_hd2·inv(S_bind)` 拽走 ⇒ **正是用户看到的那五个症状**。第 37 轮修骨轴只把撕裂 0.568→0.183 m，**没归零**。

### 3. 修法 `skeleton='native'`（现默认）

out       = Σ_b w · D[b] · src1                                           ← 网格被摆成 A-pose

### 决定性发现：**前倾只存在于绑定姿态（bind pose），游戏从不显示这一帧**

  工作态 = SYMMETRIC 轴 + T-pose（吸附在这步做）；发布态 = INITIAL 轴 + A-pose（第 6 步「转回初态 + 原始骨轴」）。
  两张 basis 表互逆 ⇒ **两次烘焙在骨架局部旋转上抵消**（`L_0·Dd·basis_t·basis_i·Dd⁻¹ = L_0`），

  这也解释了为什么参照 patch 的骨架 13 根骨 delta 全 0。
- 我们只做了后半段：`rest_sym` 用 HD2 **初态朝向**（不是 T-pose 朝向）+ 源 T-pose 关节位置，
  只烘焙一次 `basis_i`，且**从不把骨轴转回 INITIAL**。

### 2. 头号问题的机制
运行时 LBS：`v_world = Σ_b w_b · A[b] · inv(S_bind[b]) · v_bind`。
idle 时 `A[b] = rest_hd2[b]` ⇒ **只有 `S_bind[b] == rest_hd2[b]` 时 `A·inv(S_bind) = I`，顶点一个不动。**
旧 `skeleton='snap'`（把 HD2 关节吸附到源关节）⇒ `S_bind ≠ rest_hd2` ⇒ 每帧被 `rest_hd2·inv(S_bind)` 拽走 ⇒ **正是用户看到的那五个症状**。第 37 轮修骨轴只把撕裂 0.568→0.183 m，**没归零**。

### 3. 修法 `skeleton='native'`（现默认）
```

D[b]      = D[p] · rt[b] · basis_i[b] · inv(rt[b])                        ← T→A 变形，只烘网格
out       = Σ_b w · D[b] · src1                                           ← 网格被摆成 A-pose
S_bind[b] = rest_hd2[b]                                                   ← 骨架一字不改
```
- `src1` 的拟合目标从「HD2 的 **A-pose** 关节」改成「HD2 的 **T-pose** 关节」（源模型是 T-pose）。

### 实现（`tmp/rig-lab/hd2_style.py` 步骤 4d）
```python
if upper_scale != 1.0:
    hips = next(h for h in hd2 if h['name'] == 'hips')
    piv = rest_hd2[hips['index']][:3, 3].astype(np.float64).copy()
    if upper_pivot_z is not None:
        piv[2] = float(upper_pivot_z)
    z0 = piv[2] - upper_blend
    z1 = piv[2] + upper_blend
    tt = np.clip((out[:, 2] - z0) / max(z1 - z0, 1e-9), 0.0, 1.0)
    w = tt * tt * (3.0 - 2.0 * tt)          # smoothstep
    s = (1.0 + (upper_scale - 1.0) * w)[:, None]
    out = piv + (out - piv) * s
```

### 🔑 关键技术点：骨轴约定
`export_obj.bone_axis` 的注释早就写明 —— **两个引擎都把骨放在局部 +X 上**，而 **Blender 的骨
沿局部 +Y**。所以：
- `head = rest_hd2[:3,3]`（精确）
- `tail = head + L · rest_hd2[:3,0]`（骨轴 = 矩阵**第 0 列**）
- `roll`：`edit_bone.align_roll(rest_hd2[:3,2])`（矩阵**第 2 列**）

由此得到的 Blender 骨局部系 = `[-e_y, e_x, e_z]`，与 HD2 的 `[e_x, e_y, e_z]` 相差一个
**所有骨共用的固定旋转 M** ⇒ `R_p⁻¹R_c` 做相似变换、`A·inv(S)` 里 **M 完全抵消** ⇒
**变形与游戏逐位等价**（已用第 2 项验证确认）。
- ⚠️ **骨长不在游戏数据里**（`read_hd2_rig` 只读 4×4 矩阵）。用**子骨 head 的投影**
  `max(dot(child_head − head, axis))` 推导；若全为侧向子骨（`hips`→thigh、
  `chest`→clavicle）则退回**最近**子骨距离；叶子骨借父骨 0.6×；`clip(0.01, 0.55)`。
  第一版用"最远子骨距离"⇒ `chest`/`head`/`l_knee` 撞 0.40 上限，改成投影后
  `chest 0.219 / head 0.180 / l_knee 0.423 / l_foot 0.159` 才合理。

### 第一版修法（子树）为何失败 —— `probe_hd2_tree.py`

**`hips` 与 `spine1` 是 `boss` 下的兄弟**（正好解释「`spine1` 与 `hips` 完全重合」）。

默认 `fallback='region'`，CLI `--fallback` 加 `region`；52 个脚本批量 sed。

### 修法 `arm_fit`（`hd2_style.py` 步骤 **4e**，mesh-only）
逐骨残差 `d[b] = 发布头(rest_shipped[b]) − 工作头(D[b]·rest_sym[b])`，**非手臂骨置零**：

| 骨 | d | \|d\| |
|---|---|---|
| l_clavicle | (−0.0089, −0.0503, −0.1029) | 0.115 |
| l_shoulder | (−0.0947, −0.1220, −0.0956) | 0.182 |
| l_elbow | (−0.1210, −0.1071, −0.0854) | 0.183 |
| l_hand | (−0.1018, −0.0936, −0.0942) | 0.167 |
| 各手指 | ≈(−0.09, −0.08, −0.11) | 0.159–0.180 |

顶点位移 = **按 LBS 权重混合残差**，**只加到网格 `out`**（骨架绝不移动）。两个必须的补充：
1. **`arm_perp`（默认 0.0）**：只取**沿臂轴分量** `u·(d·u)`，垂直分量乘 `arm_perp`。因为 `mesh_shift`（back 0.100 / down 0.060）已经承担了垂直部分 ⇒ 全 3D 残差会**重复计算**（arm_perp=1 时手臂比参照**后移 13 cm**）。
2. **`arm_smooth`（默认 8）**：Laplacian 平滑。**不加平滑 `edge max` 2.15 → 12.43**（14 个 >5x 极小三角，原始边长 3.9–24 mm，全在**胸口/锁骨边界**：chest 得 0、l_clavicle 得 0.115 m ⇒ 权重跳变）。平滑 8 遍 ⇒ >5x 只剩 1 个、max 6.90；arm_perp=0 时 max **3.15**、bad>25% **1.00%**。

### 现象（准确措辞）

## 续 11 · 第 52 轮：肘部 6.5°（用户：小臂旋转角略偏，俯视顺时针 6.5°）

### 用户的问题（原文要点）
> 红记号 = 肘骨骼点与腕骨骨骼点；**小臂的旋转角度略有一些误差，还需要额外偏移 6.5 度（俯视图顺时针）**；
> 这个角应处于**大臂和小臂两条直线构造的虚拟局部平面**中；**分析之前的角度是如何生成的？是否可以直接叠加？**
> 先尝试调整肘部弯曲角度（当前是 T-pose 完全伸直 → 略有弯曲，现在要**减少 6.5° 弯曲**）。

### 结论：**可以，而且就是"同一个铰链少弯 6.5°"**
读 `hd2_style.py` §4（L992–1075）的生成机制：
```
R_sh = min_arc_rotation(d_up_src, d_up_tgt)                     # 肩
R_el = min_arc_rotation(d_fo_src, R_sh.T @ d_fo_tgt)            # 肘
basis[el] = inv(Rse) @ R_el @ Rse                               # Rse = rest_sym[el][:3,:3]
```
`D[el] = D[sh] . T(te) . R_el . T(-te)` ⇒ 前臂世界方向 = `R_sh @ R_el @ d_fo_src`，**按构造精确等于 `d_fo_tgt`**。

**关键实测（`_probe_elbow_axis2.py`）**：把"平面法线"搬回源坐标系后，与 `R_el` 的轴**完全同轴**
（`|dot| = 1.00000`，夹角 **0.000°**）。即：
- 左臂 `R_el = 39.642° 绕 (0.000, 0.020, -1.000)`（**≈竖直** ⇒ 所以用户能在**俯视图**看出角度！）
- 右臂完全镜像 `39.642° 绕 (-0.000, -0.029, 1.000)`
- 平面法线 `d_up_tgt × d_fo_tgt` = `(0.499, 0.006, -0.867)`（|z| = 0.867，**mostly VERTICAL**）

两种叠法**逐位相同**（A: 用平面法线共轭；B: 重解 min-arc）⇒ 选 **B（更简洁）**。

### 实现
- `retarget(... arm_elbow_open=0.0 ...)`（新参数，插在 `arm_scratch_elbow` 之后）
- CLI `--arm-elbow-open DEG`（**正数 = 掰直**，弯曲角**恰好减少** DEG）
- 做法：在 `R_el = min_arc_rotation(...)` **之前**把目标方向在平面内转一下
```python
if abs(arm_elbow_open) > 1e-9:
    n_w = np.cross(d_up_tgt, d_fo_tgt); nn = |n_w|
    d_fo_tgt = rot_axis_angle(n_w/nn, -radians(arm_elbow_open)) @ d_fo_tgt
```
- **骨架完全不动**（`basis` 只进 `D`，`rest_shipped = rest_hd2` 逐位不变）⇒ `out_idle == out` 仍成立。

### 验证数字（**基线必须带 `gain=0.05`**，见下面的坑）
管线自打印：`arm l/r: elbow ... [elbow opened +6.50 deg] -> **33.14** deg`（原 39.64，**精确 −6.50**）；肩 30.04/30.23 **未动**。

| | 前臂俯视方向（相对 −X，+Y = 前） |
|---|---|
| HD2 原生骨骼 | **+46.48°** |
| 我们 0° | **+45.96°** |
| 我们 **+6.5°** | **+39.48°** |

⇒ **误差 6.49° → 0.96°**。用户的 6.5° 基本就是正解。且"前倾角减小 = 俯视顺时针"**与用户描述一致**。

### 🔴 顺手抓到的真 bug：闭包变量 `s` 被覆盖（L736）

而 `align_pts(P) = ((P - sole) * s) @ R.T`。于是 **leg_tilt 之后所有 `joint()` 都被缩小 ~0.11 倍**。
- 现象：日志 `pivot = source shoulder` 打印 `(-0.0107, 0.0501, 0.1461)`（**踝高！**），
  关掉 leg_tilt/leg_splay 则打印正确的 `(-0.1154, -0.0331, 1.5743)`。实测对照确认。
- **对网格零影响**：`joint()` 此后只用于 `d_up_src`/`d_fo_src`（**只取方向**），
  `min_arc_rotation` 会归一化；且 `resolve_bone_map` 只用**平方距离比较**，
  均匀仿射下 `|f(a)-f(b)|² = a²|a-b|²` ⇒ 排序不变 ⇒ 映射不变。
- 修法：改名 `ct, st`。**修复后边比率指标逐位不变**（mean 1.0960/1.0955、p99 1.2826、bad 19.77%/19.75%）。

## 续 12 · 第 53 轮：手掌从腕部偏 10°（用户："钢管"模型）

### 用户的口径（两次澄清后）
> 把手臂当**钢管**：**z = 钢管轴向（手臂）**；**x = 拇指**，拇指张开后总指向**圆柱面的法向**（⊥ 手臂）；
> y 是剩下那个正交方向。要求：**把原本指向 z 的手掌向 y 偏 10°**；轴 = 拇指；
> 方向 = **手指蜷缩的旋转方向的反向** = **手掌朝手背方向翘起**；**两臂对称，自己判断轴向**。

### T-pose 手部坐标系（`_probe_hand_tpose.py`，量在对齐后的源网格 `src1` 上）——**干净得出奇**
| | 左臂 | 右臂 |
|---|---|---|
| z 钢管轴（elbow→wrist） | **(−1, 0, 0)** 正好 −X | **(+1, 0, 0)** 正好 +X |
| x 拇指（t1→t3 的径向分量） | **(0, 1, 0)** 正好 **+Y** | **(0, 1, 0)** 正好 **+Y** |
| y = z × x | **(0, 0, −1)** 正好 −Z | **(0, 0, +1)** 正好 +Z |

⇒ 用户说的"正交的几个方向"**就是世界坐标轴**，不需要任何拟合。
**两臂拇指都指 +Y ⇒ 两只手掌都是旋前（掌心向下）** ⇒ 手背侧 = 左 **+Z** / 右 **−Z**。
⇒ **伸展（朝手背）= 左 +10° 绕 +Y、右 −10° 绕 +Y**（镜像，一个符号搞定）。

### 实现
`retarget(... arm_hand_tilt=0.0 ...)` + CLI `--arm-hand-tilt DEG`（**正 = 手腕伸展 = 手掌翘起**）。
注入点 `basis[l_hand]`（在 D 递归里排在肩/肘**之后**，所以手指自动刚性跟随）：
```python
sgn = 1.0 if side == 'l' else -1.0
R_ha = rot_axis_angle([0,1,0], radians(sgn * arm_hand_tilt))
basis[h_ha] = inv(rest_sym[hand][:3,:3]) @ R_ha @ rest_sym[hand][:3,:3]
```
**没有 min-arc、没有平面拟合、没有参照拟合** —— 用户点名的轴在我们被要求工作的坐标系里就是一个世界轴。

### 验证（`_verify_hand_tilt.py`，tilt 0 → +10）
- 手长轴 `D[l_hand]·z`：`(−0.7032, 0.5874, −0.4006)` → `(−0.7774, 0.5801, −0.2431)`，夹角 **10.00°**
- Kabsch 刚体拟合：**9.9537° 绕 (0.4679, 0.8363, 0.2859)**，残差 mean 1.52 mm
  - 该轴与 `R_sh·R_el·ŷ` 的理论值 `(0.4734, 0.8373, 0.2734)` 吻合 ⇒ **就是"沿链条搬过去的拇指轴"** ✓
- 手+指 max 位移 3.51 cm（均值 1.96 cm）；腕部 LBS 过渡带 max 1.92 cm；其余部位 0

### ⚠️ 诚实的保留意见
网格层面**测不出这 10°**。`_probe_hand_plane.py`（掌面平板拟合）给出：
- 我们的掌面法线 `(0.7928, 0.3412, −0.5051)` vs 参照 `(0.8004, 0.2849, −0.5275)`
- **夹角只有 3.50°**；分解到帧里 = 拇指 +1.03° / 前臂 +2.86° / 第三轴 +2.03°

⇒ 所以 **10° 是用户从 Blender 上读出来的，不是拟合值**。旋钮是有符号的，一个数字就能翻。
诊断图 `out/hand-tilt-10.png` 同时画了 **+10（蓝）和 −10（琥珀）**，方便直接挑。
