### 实机现象（用户报告）
1. 被替换 unit **全部透明**；2. 阴影变成**围绕玩家做布朗运动的钢丝球**，每帧变化；
3. SDK 反导入 Blender：模型**抬高 1 米**（鞋底 0.9m / 最高点 3m）；4. **骨骼大量堆在世界 00**，

### 权威依据（全部在仓库内）
- SDK `stingray/unit.py::AddBoneData` 行 1796–1934：**一个 unit 的 TransformInfo 怎么拼**。
  逐骨遍历 armature；`NameHashes.index(hash)` **已存在就复用、否则追加**；
  `TransformMatrices[i] = bone.matrix`（世界）；`Transforms[i] = decompose(parent.matrix⁻¹ @ bone.matrix)`
  （**locals 是父坐标系下的局部变换**，根骨全 0）；`TransformEntries[i].ParentBone = 父骨在本表的下标`。
- SDK 行 615 / 2094–2111：`origin = matrices[MeshInfo.TransformIndex]⁻¹`；
  `Bones[i] = (origin @ M_bone).inverted().transposed()` ⇒ **mesh 变换是单位阵时 `Bones[i]=inv(M_bone)`**。
- SDK `__init__.py` 1740–1746（AutoLods）：所有 LOD 共享 lod0 的变换矩阵。
- SDK `CreateModel` 行 2375–2483：反导入时 `bone.matrix = TransformMatrices[i]`（世界），父链取 `TransformEntries`。
- 管理器 `CanonicalTransformInfoExpander.ExpandTransformInfo`：同名节点**必须覆写**（locals+matrices+parent 全取 avatar），
  `ValidateTransformInfo` 要求 **`NameHashes.Distinct().Count()==count`**（不许重复哈希）。
- 管理器 `CanonicalUnitRebuilder` 行 503–504：`MeshID` 写 +40、`TransformIndex` **照抄目标** 写 +48。

### 6 项根因（`_probe_unitdiag.py` 实测）
1. **`locals[]` 全填 0**（`DEFAULT_LOCAL`）⇒ 引擎/Blender 按父链建骨架 ⇒ 全部塌到节点 0（107/107 与 avatar 不一致）。
2. **`entries[]` 全填 `(1,0)`** ⇒ 父链压平到节点 0（avatar 是 `[(0,0),(1,0),(1,1),…]`）。
3. **`matrices[]` 全填 `IDENTITY16`** ⇒ `BoneInfo.bones[k]=inv(I)=I` ⇒ 静止时 `G_b@B_b=G_b≠I`，
   顶点被真实骨骼矩阵乱乘 ⇒ **几何炸开 = 透明 + 钢丝球阴影**。
4. **15 个重复哈希**（模板 23 节点里有 15 个与 avatar 107 骨同名，直接拼接产生 130 节点 / 115 不同哈希）。
5. **`transform_index` 写成 `8+(3-lod)`**（=11/10/9/8）；模板真值是 **lod3/2/1/0 → 5/6/7/8（全单位阵）**。
