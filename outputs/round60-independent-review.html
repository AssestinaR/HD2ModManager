1. 材质：主线程“打包正确”的结论被推翻

SDK 格式要求先连续写所有槽位键，再连续写所有 Texture ID。项目 Python 代码却交错写入。原检查又用相同错误读取器，因此形成了错误的自洽。

需修复 tmp/rig-lab/hd2_asset.py 的读取和写入逻辑。管理器现有 StingrayMaterialReferenceReader.cs 使用正确布局，无须连带修改。

内存中从干净 SDK 模板构造的14份修正材质，全部贴图引用通过；恢复旧写法，14份全部被独立检查拒绝。没有把这些候选写进游戏包。

“贴图本身很亮”只能证明文件内容，不能证明 shader 绑定到了它。缺少 PaletteSlot 就乘零的推测没有证据，不应优先采用。

2. 模板：先用 basic+ 做最小 UI 对照

候选修改内容验证目的
M1仅修贴图表，保留 basic 与旧像素引用错误对黑色的贡献
M2PBR 蓝通道0→255AO/环境通道对照
M3换完整 basic+ 模板，保留同语义三贴图优先可用候选，验证 UI 显示
M4，必要时完整 advanced 与重打包贴图、依赖basic+ 外观不够时再升级

SDK 明确标注 basic+ 和 advanced 支持 UI。basic 的来源说明并不等于它必定不支持 UI。黑色与预览缺失应分别验收。

advanced 不能只替换 parent：槽2是法线/AO/粗糙度，槽3是金属度，槽5是底色/发光遮罩，其余槽也有资源依赖。旧底色 Alpha=255 若直接作为发光遮罩，会引入新的外观问题。当前没有理由先更换已工作的56字节顶点格式。

3. 小臂：权重确有问题，但原统计混合了壳层

原探针将骨轴10cm内的皮肤、衣物和附件一起分箱。“腕端 hand 又下降”不能被解释为同一皮肤层非单调。独立分连通块后，443点手臂壳的腕端其实已经完全跟随手骨。

只让手腕及后代旋转30°，中段位移中位数左52.03mm、右52.10mm。将固定中段的手骨子树权重暂时转给肘骨，中段在此动作下位移归零；恢复旧权重，最大牵动重新达到约63mm。

这是用于证明机制的极限消融，有硬边界，不能直接发布。连通块也不自动等于皮肤，需要进一步按材质、几何和缝边确认语义。

4. 具体实施与验收

  1. 冻结已验收的最终网格。当前运行时权重来自源权重骨名映射与量化，尚未完成参考表面权重转移。
  2. 固定左右小臂、袖子、腕饰与掌指选区。主体以 elbow 为主，肘腕局部渐变；保留已良好的掌指内部权重。
  3. 腕缝按真实附着位置和相邻壳层设计，不套“所有 s>0.9L 都要 hand≥0.85”的统一规则。
  4. 分别测试腕部屈伸/侧偏、肘部屈伸、轴向扭转和组合动作；扭转骨是否需要参与，要依据动画与参考数据判断。
  5. 离线检查两体型、全部可见LOD、局部掩码外不变与权重编码，再实际 SDK 反导入最终候选。输出分壳的同视角形状图。
  6. 材质与权重分支分别验证后合并。游戏确认颜色/光泽、军械库/出击UI、持枪/换弹及原问题动作。
