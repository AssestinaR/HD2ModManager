## 1. 权重：已经和原版一致 —— 权重这条路走到头了

新探针 `_probe_twist_lag.py`（只读）测的是**眼睛看到的东西**，不是权重本身：

扭腕时游戏把 `l_hand` 转 θ、`l_hand_twist` 转 0.78θ（300 个真实动作的中位比），
其余骨不动，所以每个顶点的**实际转角因子**

```
f(v) = w_hand(v) + 0.78 * w_twist(v)         1.00 = 完全跟手，0.78 = 完全不跟
```

腕带 `|t| <= 45 mm` 内 f 的**极差**（这就是"针柄在 2 点、针尖在 3 点"的量化）：

| | 腕带 f 极差 | θ=90° 时的角度差 |
|---|---|---|
| **我们（出货包）** | **0.233** | **21.0°** |
| **原版手臂皮肤** | **0.235** | **21.2°** |

⇒ **一模一样。** 原版自己也有这 21° 的滞后（这是游戏 0.78 扭转比的设计），
所以这 21° 不是缺陷。**权重已经对齐原版，继续调权重不会有任何改善。**

顺带解释了"第 74 轮为什么没改善"：第 74 轮修的是真 bug，但只动了
**16 332 696 字节里的 22 728 字节（0.14%）**，且只影响小臂最末端 10%——
太小，看不出。

> 复核过的一致性：手骨权重爬升位置（我们 `0.1@-16 / 0.5@+3 / 0.9@+21`，
> 原版 `0.1@-18 / 0.5@-9 / 0.9@0`，相差 10~20 mm，同量级）。

## 3. 🔴🔴 真凶：小臂网格整体偏离了肘→腕骨骼轴

新探针 `_probe_arm_axis.py` / `_probe_arm_sections.py` / `_probe_arm_overlay.py` /
`_probe_arm_bone_overlay.py`（全部只读）。

**判据**：把网格顶点投影到"垂直于骨轴"的平面上，看它们落在骨轴的两侧还是单侧。
骨轴在网格内部 ⇒ 投影会**跨过 0**（有正有负）。

| 身体段 | 我们（出货包）沿偏移方向的范围 | 骨轴是否在网格内 |
|---|---|---|
| `spine1→spine2`（躯干） | −246.8 .. +236.8 mm | ✅ 在里面 |
| `l_thigh→l_knee`（大腿） | −114.8 .. +131.1 mm | ✅ 在里面 |
| `l_knee→l_foot`（小腿） | −53.8 .. +100.9 mm | ✅ 在里面 |
| `l_clavicle→l_elbow`（上臂） | −153.2 .. +128.5 mm | ✅ 在里面 |
| **`l_elbow→l_hand`（小臂）** | **−1.2 .. +81.3 mm** | ❌ **只在单侧，骨轴贴在网格边缘** |

按材质拆开看小臂（排除"被某个装饰件带偏"的可能）：

```
我们   小臂带 t/L 0.15..0.85：mat 1  n=131  centroid 35.1 mm  范围 −0.4 .. +80.4
                              mat 7  n=124  centroid 34.9 mm  范围 −1.3 .. +81.3
原版   小臂带 t/L 0.15..0.85：mat 0  n=140  centroid 15.1 mm  范围 −41.6 .. +74.1
```
**两个材质都一致**：我们的整个小臂只落在骨轴一侧，跨不过去。
偏移方向 = `+N_ = (0.725, 0.689, 0)`（单位空间），即**朝身体中线内侧 + 朝前**，
腕带附近约 36 mm，最远处（靠肘）约 46 mm。

肉眼证据（`_log/r75/`）：
- `r75-bones-ours.png` vs `r75-bones-vanilla.png`：把 `shoulder→elbow→wrist→hand`
  用红线画在手臂上——**原版红线穿在手臂正中，我们的红线贴着小臂上缘走**，
  整条小臂挂在骨线下面。
- `r75-overlay-0.15.png`：同一坐标系里，蓝点（原版）围成**以红十字为中心**的环；
  橙点（我们）**整团偏在一侧**，骨轴落在手臂外缘。
- `r75-forearm-full.png`：整条小臂的轴向投影，同样结论。
- `r75-twist-ours.png` / `r75-twist-vanilla.png`：同条件扭转渲染对照。

### 为什么这正好解释"钟表指针"

`l_hand` 和 `l_hand_twist` 的 pivot 都在**腕骨 head**，扭转轴 = 肘→腕连线。
如果这条轴落在小臂**边缘**（离小臂中轴 ~40 mm、离外表面最远 81 mm），
那么"绕轴自转"就必然带着整条小臂**绕一个偏心的圆公转**：

```
公转位移 = 2 * 偏心量 * sin(θ/2)      偏心 40 mm、θ=90° ⇒ 约 57 mm
```
**偏心 0 才是纯自转。** 原版偏心 15 mm，我们 35~46 mm —— 差出来的这 20~30 mm
就是用户看到的手腕对不齐。**这是几何问题，权重怎么调都修不掉**，与第 74 轮
"没改善"完全吻合。

### 与用户判断的关系

用户第 74 轮的判断（"手腕骨骼不在手腕处的网格中心，绕骨旋转产生绕轴位移而不是
纯自转；因为我们的手臂摆放是纯角度的"）**完全成立**，本轮只是把它量化了，
并且发现它**不止手腕，是整条小臂**。

## 5. Blender 要不要用户亲自操作？—— **不需要**

两条理由：

1. **Blender 可以完全无人值守地跑**：
   `blender --background --python xxx.py`，脚本里用 `bpy` 干完所有事，
   用户连界面都不用开。需要"看"的时候，我渲成图片发过去即可。
2. **这一轮的修法根本用不上 Blender**。第 74 轮 §4 说的 "Surface Deform 拿原版
   手臂当贴合目标" 会把我们的外形也改成原版（用户明确说"不动我们的外形"）。
   而本轮的问题是一个**纯粹的顶点位置校正**：把偏离的网格搬回骨轴上，
   用同一套 Python 管线（和 `reweight_forearm_twist.py` 同一层）就能做，
   可复现、可回退、可逐字节核查。

## 6. 下一步（建议）

**把重定向从"整体刚体"升级成"关节级对齐"**（= 第 74 轮 §4 的方案，本轮有了硬证据）：

1. **最小实验**：只做左小臂。取 `elbow→wrist` 轴，逐站测出网格中轴相对骨轴的
   偏移量，构造一个**平滑校正位移场**把网格搬到骨轴上；
   在肘、腕两端**渐隐到 0**，避免接缝裂开（肘接上臂、腕接手）。
2. **验收**：用本轮同一批探针复测——小臂带必须变成"跨过 0"；
   `r75-overlay` 的橙点必须围住红十字；扭转渲染偏心必须降到原版量级。
3. **再实机**：通过后替换交付包，跑 `library sync` 四段。
4. 通过后推广到右臂、双腿（本轮已确认双腿与上臂本身是对的，只需复查）。

**风险（要提前说）**：校正会把小臂往**外侧/后方**搬 20~40 mm，外形会变。
若肩部因此裂开，就需要把校正范围扩到 `clavicle→elbow` 一起做（做整体手臂对齐），
而不是只做小臂。

**备选方案**：改 unit 里的骨轴位置（把 `l_hand`/`l_hand_twist` 的 head 挪到网格中心）。
不动网格、不改外形，但**改的是全游戏共享的骨架**，风险高，暂不建议。
