# 第 74 轮 · 手腕错位的诊断与「自动姿势匹配」工具调研

日期：2026-10-14
背景：第 73 轮把 `l_elbow → l_hand_twist → l_hand` 的权重修好并出货后，用户实机测试
报告**手腕仍有错位**——"钟表指针想去 3 点，针柄只在 2 点、针尖却在 3 点"，且**多发于
手腕绕手臂轴旋转时**。用户观察后提出假设：**手腕骨骼不在手腕处网格的中心**，所以绕骨
旋转实际产生了"绕轴位移"而不是纯自转；并怀疑根源是**我们的手臂摆放是"纯角度"的**，
源模型 T-pose 略有差距就会累积成关节错位。

### 1.2 几何：我们的网格相对骨骼**确实比原版偏得多**

同一探针测"每一档截面的质心离骨骼轴的距离"：

| t (mm) | 我们 偏移(mm) | 原版 偏移(mm) |
|---|---|---|
| -80 | 30.84 | 13.63 |
| -60 | 29.42 | 13.46 |
| -40 | 24.82 | 12.88 |

| 0 | 16.29 | 18.97 |

手腕环（|t| ≤ 20 mm）质心离轴：**我们 19.97 mm / 原版 15.36 mm**。

⇒ 小臂中段我们的截面质心偏移是原版的 **2 倍左右**。这**不能单独证明**"骨骼不在网格
中心"（两个模型的截面形状本来就不同，质心偏移受截面不对称影响），但**方向与用户的判
断一致**：我们的网格相对骨骼的几何偏差确实更大。**要下定论需要更强的指标**

### 1.3 扭转渲染：手腕褶皱与"0.78 扭转比"无关

新探针 `_probe_wrist_twist_render.py`（只读）用**真实合成模型**渲染扭转：
`l_hand` 转 θ、`l_hand_twist` 转 0.78θ（0.78 是 300 个真实动画测出的中位比），两骨共享
腕部 pivot。结果（`E:/tmp/r74-twist-ours.png`）：

- 手腕处出现明显的**尖刺/褶皱**；
- 但 **"realistic（θ / 0.78θ）"与"rigid（两骨同 θ）"两行画面完全一样**。

⇒ 这个手腕瑕疵**不是** `l_hand` 与 `l_hand_twist` 的扭转比例差造成的，而是**手腕处本身
的结构问题**。最可疑的是第 72 轮发现的那个"**只在 0.88–1.05 腕环、几乎刚性**"的
`mat_metal` 甲壳——扭转时它与皮肤互相错开就会冒尖。**待验证（§3）。**

## 2. 用户的判断：我们的重定向"只有整体，没有关节级"

**成立。** 我们的 `retarget` 是 **yaw 拟合 `R` + 统一缩放 `s` + 平移 `t`（锚"头顶"）**，
即**整具模型一次刚体变换**。它只能保证"整体朝向/身高"对，**不能**保证每个关节落到 HD2
关节上。只要源模型的 T-pose 手臂与 HD2 的 A-pose 手臂在**角度或骨长比例**上有差，
误差就会全部堆到关节处——手腕最敏感（杠杆最长、又叠加腕环这种刚性壳）。

⇒ **需要的是"关节级"对齐**，而不是继续调角度。

## 3. 现成工具调研（按"能不能解决我们的问题"排序）

### ★ 最对口：骨架级姿势重定向（skin-transfer retarget）

思路：给源网格配上**源骨架 + 蒙皮权重**，把源骨架**逐骨对齐**到目标骨架，让网格**蒙皮
变形**（而不是刚体旋转），再烘出顶点。这样每个关节天然落在目标关节上。

| 工具 | 授权 | 备注 |
|---|---|---|
| **Auto-Rig Pro**（Quick Rig / Remap） | 商业 | 业界最常用；有 "automatic leg and arm angle correction" |
| **Rokoko Blender addon** | 免费 | 动作重定向，需要 Rokoko 账号 |
| **gret · Mesh: Retarget** | **开源** | `github.com/greisane/gret`。用 **RBF** 重定向网格或**骨架**；对骨架可"把体型比例变化应用到 rest pose"。⚠️ 对**网格**要求源/目标**拓扑与顶点顺序一致**，对我们（L4D2 vs HD2）不直接可用；**但 RBF 这个思路正是我们要的** |
| **LM_SwapRestPose** | **开源** | `github.com/luca-malisan/LM_SwapRestPose`。把 T-pose ↔ A-pose 互换并保留原 rest 为关键帧 |
| **Blender 原生** | 免费 | `Copy Transforms` 约束 + `Pose → Apply → Apply Pose as Rest Pose`；配合 `Automatic Weights` |

### ★ 姿势归一化（把骨架摆成标准姿势）

| 工具 | 授权 | 备注 |
|---|---|---|
| **AutoTPose** | **开源** | `github.com/4onstudios/AutoTPose`。自动识别上臂/前臂并对齐到干净 T-pose，用**几何启发式**（不依赖骨名），有 **headless CLI**，可输出报告。**这是我们"别再手搓角度"最直接可借的参考** |
| Mixamo / AccuRIG | 免费/商业 | 云端自动绑定 + 姿势标准化 |

### ★ 非刚性网格配准（把我们的网格"贴"到原版身体上）

思路：原版 HD2 手臂网格与 HD2 骨架**天生精确对齐**。把我们的手臂非刚性配准到它，
关节位置就自动正确。

| 工具 | 授权 | 备注 |
|---|---|---|
| **pycpd** | **开源** | Coherent Point Drift，纯 numpy，刚体/仿射/**非刚性**三种 |
| Non-rigid ICP (Amberg 2007) | 论文 | 有多个开源实现 |
| Blender `Surface Deform` / `Mesh Deform` / `Shrinkwrap` | 免费 | 内置；`Surface Deform` 可把网格绑到另一个网格表面 |
| R3DS Wrap / Wrap4D | 商业 | 网格"包裹"的行业标杆；**方法论值得学**：用一个干净模板去"覆盖"混乱源网格 |

### ★ 权重迁移（本轮不是问题，但值得记下）

**Blender `Data Transfer` 修改器**（Vertex Groups → *Nearest Face Interpolated*）：
可以把**原版手臂的权重**直接按最近面插值搬到我们的网格上。省掉全部手工调权。

### ★ AI 自动绑定（用来"给网格生成正确骨架"）

| 工具 | 授权 | 备注 |
|---|---|---|
| **UniRig** | **开源** | SIGGRAPH 2025，`github.com/VAST-AI-Research/UniRig`。一次输出关节位置 + 父子关系 + **蒙皮权重** |
| **RigNet** | **开源** | SIGGRAPH 2020，`github.com/zhan-xu/RigNet`。`pKrime/brignet` 是它的 Blender 插件（作者标注已失效） |

## 4. 我的建议

**结论：不要换"整体角度"的调参，把重定向从「整体刚体」升级成「分段刚体 + 平滑混合」。**

这本质就是**一次 LBS（线性混合蒙皮）重定向**，步骤：

1. **源骨 ↔ HD2 骨映射**（C# 侧 `HD2SourceMigration` 已有雏形，Python 侧需要一份表）。
2. 对每根骨求"**源骨 rest → HD2 骨 rest**"的刚体变换（位置 + 朝向）。
3. 用**顶点到骨段的距离**做权重混合（类似 bone heat），得到每个顶点的合成变换。
4. 应用 → **每个关节精确落到 HD2 关节**，且过渡平滑。

**要借的工具/思路**：
- **gret 的 RBF 重定向**——把"点对点映射"做成光滑函数，正是第 3 步的高级版；
- **Blender `Data Transfer` 的最近面插值**——第 3 步的工业实现；
- **AutoTPose 的几何启发式**——自动识别手臂骨、不依赖骨名。

**如果要最省事**：在 Blender 里用**原版手臂网格**做 `Surface Deform` / `Mesh Deform` 的
贴合目标，只借用它的**关节位置**，不动我们的外形。

## 7. 追加（同轮）：手腕错位的**直接**原因已找到并修好

§1.3 说"手腕褶皱与 0.78 扭转比无关"，但当时没定位。继续查之后找到了，
而且**不是**几何摆放问题，是**第 73 轮自己引入的**一个 bug。

### 7.1 一个 5 mm 的台阶

`reweight_forearm_twist.py` 的 ROI 是

```python
roi = (rad < args.radius) & (t > 0.0) & (t < L)     # t 从【肘】算起，L = 小臂长
```

而第 73 轮新加的"手腕交接档"是 `--hand-start 0.90 --hand-end 1.12`，
按 `t/L` **跨过腕（1.0）**。**ROI 在腕处硬切**，交接档只走到一半：

| t/L | 原版 twist | 第 73 轮出货 | 第 74 轮修正 |
|---|---|---|---|
| 0.94 | 0.915 | 0.906 | 0.906 |
| 0.98 | 0.750 | 0.688 | 0.688 |
| **1.02** | 0.290 | **0.000 ← 断崖** | **0.421** |
| 1.06 | 0.049 | 0.000 | 0.207 |
| 1.10 | 0.008 | 0.000 | 0.025 |
| 1.14+ | ~0 | 0.000 | 0.000 |

### 7.2 后果：同位置的壳转的角度不同

按材质分壳实测（扭转 60°，twist 骨按实测 0.78 同转），腕带 |t| < 45 mm：

| 壳 | 顶点数 | w_twist | **实际转角** |
|---|---|---|---|
| mat 0（近轴，腕环） | 41 | 0.816 | **47.8°** |
| mat 1（皮肤/护手） | 1680 | 0.337 | **60.0°** |

**差 12.2°**（θ=150° 时约 20°）——就是"针柄在 2 点、针尖在 3 点"。

### 7.3 修正

1. `t_end = max(L, args.hand_end * L)`；`roi = ... & (t < t_end)`
2. `arm_names` 收窄为 `{elbow, hand, twist}`（原来是**整个手部子树**，
   ROI 一过腕就会抹掉手指权重）
3. "是否改动"改为**与顺序无关**的比较

### 7.4 验证

- **字节负对照 PASS**：22728 / 16332696（0.139%），全在 `bone_weight`+`bone_index`，
  **字段外 0 字节**，两 stream 对称，**TOC 未动**。
- **影响范围**：用 r72 参数重跑，ROI 加长只动**每侧 10 个顶点**（t/L 1.02~1.12，
  腕后手根的残留肘权重）——是修正不是回归。
  ⚠️ 因此"旧参数重跑 = 逐字节相同"这条负对照**不再成立**（算法改动）。
- ⚠️ 本 unit 的 `remaps` 是**恒等**（8 材质 × 107，全 identity），所以
  `reweight_forearm_twist.py` 不 remap 对我们是安全的；**换 unit 前必须补**。

### 7.5 仍然存在的手腕瑕疵（未定位）

扭转渲染里腕部仍有一个**星形褶皱**，但它在"两骨同 θ"与
"手 θ + twist 骨 0.78θ"两种模型下**完全一样** ⇒ **不是扭转比例造成的**。
下一步应按壳测纯扭转下的真实位移场，确认是不是腕环那个"近刚性"壳。

### 7.6 这与"整体刚体重定向"的关系

§1.2 的几何偏差（我们的截面质心偏移是原版 2 倍）**仍然存在**，
是"手腕总对不齐"的**结构性**来源；本轮的 ROI bug 是**叠加**在它上面的
一个独立缺陷。两者都要处理——前者靠 §4 的分段刚体重定向，后者已修。
