# HD2ModManager 约束事实

仅记录实现中容易被误判的硬限制。
UI 是占位调用层；先保证 Core/Adaptation 的功能、事实和输出正确。

## 分层

- Manager：用户输入、调用 Core、显示进度和结果；不解析或写出 Patch。
- Core：业务流程、稳定事实、候选选择、输出策略和文件事务。
- Adaptation：Patch、Game Data、Unit、Material、Texture、GPU 的读取、重建、写出和回读。

## 稳定事实

- 已导入 Mod 的 AssetKey 与引用边以 SQLite facts 为权威；页面和 Core 的决策不得重新完整扫描 Patch。
- 最终写出可以按已批准 AssetKey 读取 payload；这不是重新分析。
- AssetKey 存在于多个 Game Data archive 时，事实必须保留多个目标，不能把首个 archive 当作唯一归属。
- “不在 Mod 内嵌”不等于“缺失”或“必须由材质包提供”。

## Unit 更新与材质

- Patch 重建的唯一目标是更新失效的 Unit；材质、贴图和其他正常资源不是重建流程的职责。
- 重建时保留所有 source Unit 的 Material AssetKey 引用；不解析、验证、替换、内嵌或清空这些引用。
- 极小化的 current target-shell mesh 保留 current target 的 Material AssetKey 引用。
- 纯 Unit 包、内嵌材质包、外置材质包和混合包都可更新 Unit；没有内嵌材质、没有可识别配套材质包或引用无法判定，都不能阻止 Unit 更新。
- 外置材质或其他 Mod 提供的资源仍按原有部署关系工作；更新后的 Unit 仅保持对其原 AssetKey 的引用。
- 拆分内嵌材质、合并材质、查找配套材质包和材质闭包诊断是 Mod 管理器的独立实用工具，不得成为 Patch 重建的前置或隐式步骤。

## 同 AssetKey 重建

- 输入 Patch 只删除旧 Unit 和旧 Composite Unit，写入以 current Game Data target Unit 为壳的重建 Unit。
- 每个 current target mesh 必须被替换或极小化；不得遗漏；输出不得保留旧 source Unit 或旧 Composite Unit。
- 除被删除的旧 Unit/Composite Unit 和新写入的 Unit 外，必须原样保留输入 Patch 的所有条目，不按资源类型筛选或重组。
- 必须原样保留输入的 `.stream`、`.gpu_resources` 及其余 sidecar；保留条目的 payload、引用和 archive 归属不得因 Unit 更新改变。
- `stream`、`gpu_resources` 的每个引用范围必须在输出 sidecar 中有效。
- 保留的条目若有 `StreamSize > 0`，输出必须保留或重建 `.stream`。
- 内部回读只证明结构性约束；Blender 和游戏验证仍是外部验收。

## 跨护甲 target-shell 重建

- 该链路只在已批准的跨护甲 candidate 中启用；same-key/纯 Patch 重建不得支付 TransformInfo 扩容、inverse-joint 重建或跨空间顶点转换的成本，也不得继承其容错逻辑。
- `BoneInfo.RealIndices` 是目标 `TransformInfo` 的索引，不是 source index；顶点 bone index 又是当前 material section 的 fake index。必须先按 source section fake index 解出 source bone hash，再定位 current target transform，最后按输出 section remap 重新编码；把三种 index 当作同一种会产生局部拉伸、左右体型错位或动作异常。
- 跨护甲重建的完整来源 palette 不能假设每项都被活动顶点使用或都存在于 target `TransformInfo`。只可丢弃不存在于 target 的未使用 palette 项，并同步压缩每个 remap；若活动 influence 无法映射，必须阻止写出，不能回退为 index 0。
- 同一组 source 骨骼在 target 中的 `RealIndices` 和 section fake-index 排列应保留 source 的有效顺序；不能用 target 壳既有 palette 顺序重新排序。顺序相同的集合仍会改变顶点 index 的语义。
- 目标 inverse-joint matrices 必须由 current target `TransformInfo` 相对于当前 mesh transform 重新计算，并与 source→target mesh-space 的**位置**转换成对启用；只改其中一侧会使模型整体漂移、胖瘦壳不重合或绑定错误。
- 不得对 normal、tangent、bitangent 套用通用矩阵公式后写回。已验证这种做法会在位置和蒙皮正确时造成胸部材质斑驳；在未逐字节复刻 SDK 的 tangent-basis 规则前，跨空间重建仅转换 position，保留 source 表面向量的原始编码。
- 胸部的 render family 可能跨多个 sibling LOD/mesh；单个 LOD0 可写出且游戏可加载，不代表已覆盖实际渲染路径。不得用通用 section expansion 猜测补齐：source/target section 数、material slot 与 BoneInfo remap 不完全一致时必须保持已批准 mapping，后续应从人工 SDK 输出反推精确布局。
- `BoneInfo`/`TransformInfo` payload 增长必须显式启用可变长度 relocation，并在写出后回读；只要任一 target mesh 仍引用旧 palette 或旧 matrix，局部部件就可能只在游戏中失效。

## 失败处理

- facts 缺失、过期或无法确定 current target Unit 时：阻止操作并提示刷新事实。
- 材质引用是否可由 Game Data、当前包或其他 Mod 满足，不是 Unit 更新的阻断条件。
- 不允许以“重新完整扫描输入 Patch”作为普通操作的隐式回退；已批准条目的 payload 读取与原样保留不属于重新分析。
