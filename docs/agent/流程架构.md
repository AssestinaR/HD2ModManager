# C# 简化版 SDK 风格护甲替换架构

本节不删除或替代上面的 SDK 原始流程，而是定义不依赖 Blender、面向 HD2ModManager 的等价压缩流程。

“简化”只删除 Blender 的交互性绕路和不产生最终资源事实的中间步骤，不删除 SDK 保存阶段真正负责兼容性的重建、计算、序列化和依赖处理。

## 核心目标

```text
source Patch 的真实可见模型
   -> 目标 Game Data Unit 模板
   -> 明确的 source Unit/Mesh -> target Unit/Mesh 规划
   -> 目标未命中模型极小化
   -> source 模型合并到 target 模型语义
   -> SDK 等价的 RawMesh/Section/Material/Bone/Stream/GPU 重建
   -> 仅写入需要的目标资源和依赖
   -> 新 Patch 统一布局并验证
```

简化版不模拟 Blender Object、Collection、Armature modifier 或 UI 操作；但必须保留它们在 SDK 保存前后产生的有效资源语义。

## 与 SDK 原始流程逐步对应

### 1. Patch 会话

SDK：`Default Archive -> Active Archive -> CreatePatchFromActive() -> 空 Patch`。

C#：`当前 Game Data/Default Archive -> 目标读取上下文 -> 独立空输出 Patch 会话`。

去掉：Default Archive 的 UI 状态、整个 Archive 的内存深拷贝、Active Patch 切换操作。

保留：目标资源必须来自当前 Game Data/Search Archive；输出 Patch 不能默认以 source Patch 的 Entry 集合作为模板；Entry 来源、所有权、依赖和 sidecar 布局必须显式记录。

对应 SDK：`CreatePatchFromActive()`、`GetEntryByLoadArchive()`、`AddEntryToPatchID()`。

### 2. source 模型提取

SDK：`Load Unit -> Import Unit -> 删除空/极小 Blender Object`。

C#：`读取 source Unit -> 读取 RawMesh/MeshInfo/Section/材质槽/Stream/骨骼/变换 -> 分类 source Mesh -> 保留真实可迁移模型语义`。

去掉：Blender 对象创建、场景删除和 UI 操作。

保留：空、极小、无法解析的 Mesh 必须分类；source 的顶点、索引、材质槽、UV、法线、颜色、权重、部件身份和坐标空间必须进入中间模型。

对应 SDK：`LoadStingrayUnit()`、`ImportStingrayUnitOperator`、`GetObjectsMeshData()` 输入侧。

### 3. target 模型与规划

SDK：`Search Archive -> GetEntryByLoadArchive(... IgnorePatch=True) -> Load target Unit -> Import target Unit`。

C#：复用 Manager 已有规划器生成明确的 source Unit/MeshInfoIndex 到 target Unit/MeshInfoIndex 映射；执行器只接收已确认映射，不在 Adaptation 内重新猜测。

保留：target 必须从当前 Game Data 读取；保留 Unit 身份、MeshInfoIndex、LOD family、TransformInfo 和目标结构；映射不明确、LOD/骨骼缺失或 Section 关系无法解释时阻断写出。

对应 SDK：`GetEntryByLoadArchive()`、`LoadStingrayUnit()`、`CreateModel()`。

### 4. 无 Blender 的最终模型语义

SDK：`target tiny Mesh -> source 坐标变换 -> Blender object.join() -> 合并 topology/material slots/vertex groups/UV/normal/color`。

C#：

```text
TargetMeshSemantic
   -> 未命中 target Mesh：构造 SDK 兼容 tiny RawMesh
   -> 命中 target Mesh：创建 FinalMeshSemantic
   -> source 几何变换到 target 局部空间
   -> 合并顶点属性、三角形、材质槽和骨骼权重
   -> 保留 target Unit/Mesh 身份
```

去掉：Blender Object、active object、Collection、source object 删除和人工选择。

保留：target 身份、坐标变换、拓扑/index、材质槽与 polygon material index、vertex group/权重、UV/normal/color 合并。这里不是简单覆盖 RawMesh，也不是无条件追加 source 二进制。

对应 SDK：Blender `object.join()` 之后、`PrepareMesh()` 之前的最终对象语义。

### 5. SDK 等价的 PrepareMesh/GetMeshData

SDK：UV/sharp edge 拆点、法线处理、三角化、权重归一化、四 influence 限制，再生成 `RawMesh.Materials` 和顶点/索引/骨骼数据。

C#：对 `FinalMeshSemantic` 做纯 C# 几何和属性规范化；按目标 Stream ABI 编码；按目标 TransformInfo/BoneInfo 重建骨骼；按材质槽生成 RawMesh；为目标 Unit 的全部相关 LOD 生成最终 RawMeshes。

去掉：Blender Mesh 副本、Blender operator、modifier 和 vertex group 对象。

保留：不得直接复用已量化 source GPU bytes；必须重新编码顶点属性；权重规则必须明确；BoneInfo、RealIndices、FakeIndices、remap 和 inverse-joint 必须整体重建；Material 数量和 Section 语义来自最终模型；所有 LOD 策略必须明确。

对应 SDK：`PrepareMesh()`、`GetMeshData()`、`BoneInfo.SetRemap()`。

### 6. 从全部 RawMeshes 重建 Unit

SDK：`RawMeshes[MeshInfoIndex] = mesh -> Entry.Save() -> StingrayMeshFile.Serialize() -> SerializeGpuData()`。

C#：`TargetUnitModel.RawMeshes[MeshInfoIndex] = FinalRawMesh -> 重建 Section/Material/BoneInfo/TransformInfo/StreamInfo -> 从全部 RawMeshes 重新生成 GPU buffer -> 重新计算所有 Unit offset/size/alignment`。

去掉：Python Entry 对象和 Blender 全局状态。

保留：必须以全部目标 RawMeshes 统一序列化，不能在旧 Unit TOC 上局部替换；Section、Material、BoneInfo、Stream、GPU 和尾部 offset 必须来自同一次重建；未知区段只能在确认地址空间和保存语义后保留。

对应 SDK：`Entry.Save()`、`StingrayMeshFile.Serialize()`、`SerializeGpuData()`。

### 7. 依赖处理

SDK：`SaveMeshMaterials()`，并按实际变化保存 Bones、StateMachine、Animation。

C#：分析最终 Unit 依赖，验证 Material/Texture 闭包，按策略复制、复用或回退；仅加入实际需要的 Bones/StateMachine/Animation/Composite；删除不应保留的 source Unit/Composite/Entry。

去掉：Blender 材质节点扫描和 UI 保存。

保留：Material/Texture 闭包必须可审计；目标材质和 source 材质必须有明确策略；Unit、Composite、Bones、StateMachine、Animation 引用闭包必须一致。

对应 SDK：`SaveMeshMaterials()`、`AddEntryToPatchID()` 以及各依赖 Entry 的 `Save()`。

### 8. 新 Patch 写出

SDK：`Active Patch Entry 字典 -> Entry.Save() -> TocEntry.SerializeData() -> StreamToc.Serialize()`。

C#：建立 `CanonicalPatchSession`，只收集最终目标资源和必要依赖；删除被替代 source Unit/Composite；统一写出 TOC、GPU sidecar、stream；重新计算 EntryIndex、offset、size 并按 64 字节对齐；执行回读、引用、范围和游戏前静态验证。

去掉：SDK 字典/UI 实现和无关 source Patch 条目。

保留：输出必须是明确 Entry 集合的新会话，而不是 source Patch 的默认保留副本；每个 Entry 的 TOC/GPU/stream 所有权必须明确；sidecar offset 必须范围有效且对齐；条目集合必须符合引用闭包。

对应 SDK：`TocEntry.Serialize()`、`TocEntry.SerializeData()`、`StreamToc.Serialize()`。

## 压缩项与保留项总表

| SDK 工序 | C# 去掉 | C# 保留的等价语义 |
|---|---:|---|
| Default Archive UI 会话 | 是 | 目标 Game Data 读取基线 |
| `CreatePatchFromActive()` UI/对象流程 | 是 | 独立空 Patch 会话 |
| Blender Import Unit | 是 | 直接读取带身份的 Unit/Mesh |
| 删除空 source Object | 是 | source Mesh 分类 |
| Blender tiny Mesh 操作 | 是 | SDK 兼容 tiny RawMesh |
| `object.join()` | 是 | 最终模型语义合并 |
| Blender `PrepareMesh()` operator | 是 | 纯 C# 几何/属性规范化 |
| `GetMeshData()` | 是 | 直接生成 RawMesh 中间表示 |
| `BoneInfo.SetRemap()` | 否 | 按 SDK 规则移植 |
| `StingrayMeshFile.Serialize()` | 否 | 完整 Unit/GPU 重建 |
| `SerializeGpuData()` | 否 | 从全部 RawMeshes 重建 buffer |
| `SaveMeshMaterials()` | 否 | 显式依赖闭包策略 |
| Bones/StateMachine/Animation 保存 | 否 | 按实际引用变化写入 |
| Blender/SDK Patch UI | 是 | Entry 集合、所有权和布局语义 |

## 对当前实现的边界判断

现有 `SdkStyleTargetShellUnitReconstructor`、`SdkStyleMeshReencoder`、`UnitMeshWriter` 和 `PatchArchiveWriter` 可以复用读取、RawMesh 和底层二进制能力，但不能宣称已经实现本简化架构。

后续应明确以下独立模块：

```text
SdkStyleReplacementPlan       // 复用 Manager 已生成的明确映射
CanonicalMeshSemanticMerger   // 无 Blender 的 join 等价语义
CanonicalMeshPreparation      // PrepareMesh/GetMeshData 等价规范化
CanonicalUnitRebuilder        // 全部 RawMeshes -> Unit/GPU 重建
CanonicalDependencyClosure    // Material/Texture/Bone 等依赖闭包
CanonicalPatchSession         // 空 Patch、Entry 所有权和统一布局
```
