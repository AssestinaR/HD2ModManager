## 1. 口径：什么是「孪生组」

1. **纳入范围**：复用 `SectionalExclusivePlanner.IsNamed` 与 `KitNonPlayerArmors`，仅限有正式名字的玩家护甲与玩家头盔：
   - 排除 `0x…` 未命名记录；
   - 排除 `KitNonPlayerArmors` 中「拿不到」的非玩家护甲（`2107035846`、`1969314276`）与非玩家头盔（`1303420068`、`2015397810`、`2606482720`、`88270577`）；
   - 民主官 NPC（`124623533`）保持单列，不进孪生组。
2. **等价判定**：非披风（`slot != 1`）部件布局完全相同——比较记录的 `(unit_file_id, slot, piece_type, raw_body_type)` 规范化有序集合完全一致（对称等价关系）。
   - 因选品器已按正式名合并多版本（如 `B-01“战术”` 的 9 条记录），若两个同名组各自包含至少一条布局完全相同的非披风记录（并查集传递闭包），则这两个同名组归入同一个孪生组。
   - 仅当等价类包含 **≥ 2 个不同正式名** 时，才构成孪生组。
3. **集中开关**：在 `ArmorMappingPickerPlanner` 提供集中开关 `TwinBundlingEnabled`（默认 `true`），所有构建与补齐入口均以它（及可选覆盖参数）为准。将来做好私有零件分离方案后，关闭此开关即可恢复单独映射。

## 3. 界面、套装与 2 槽规则（已拍板）

1. **合并成一行（方案 A）**：
   - 护甲 / 头盔选项卡中，同一孪生组合成一行，名称按组内名字排序以 `" / "` 连接（例如 `B-01“战术” / B-16“百战老兵” / B-22“模范公民” / TR-40“金鹰” / TR-7“形象大使”`）。
   - 行标「换色孪生 · N 套」（`TypeLabel` / `ActivationLabel`），并在 `Summary` / `Note`（行内及悬停提示）说明：**「只是颜色不同，游戏里分不开，只能一起换」**。
   - 搜索组内任意名字或成员 ID 均可命中该行。
   - 映射这一行 = 把组内全部成员 `MemberItemIds` 映射到同一个视觉来源；取消映射同理，整组一起取消。
   - 左侧「映射目标」列表（`BuildTargetGroupPlans`）按同一口径合并显示，避免左侧拆散。
   - **全量模式与低污染模式均开启捆绑**。
2. **套装选项卡与 2 槽规则**：
   - **护甲与头盔一一对应的孪生组**（护甲组 1 + 头盔组 1、护甲组 2 + 头盔组 2）：直接合成一行孪生套装，包含整组护甲成员与整组头盔成员。
   - **仅头盔孪生、护甲不同的组**（`CM-14` / `TR-117`、`FS-23` / `TR-62`）：
     - 两套护甲各自独立成套装行，但它们的 `HelmetMemberIds` 展开为整个头盔孪生组（在 3 槽 / 全量模式下，选中或已映射其中一套时，另一套因头盔冲突而置灰并写明原因）。
     - **2 槽（头身合并）压缩素体下**：`EvaluateProjection` 与添加映射到左侧时，仅头盔孪生的套装不把头盔孪生组带入（只写护甲成员，且 `EvaluateManagedAndTwoSlot` 不因孪生头盔已映射而阻塞另一套护甲），保证 `CM-14` 与 `TR-117`、`FS-23` 与 `TR-62` 在 2 槽下互不阻塞。
3. **冲突置灰联动**：`ApplySelectionConflicts` 继续基于 `MemberItemIds` 交集判定，整组天然作为一个单位参与跨选项卡联动。
4. **不改共用控件**：复用 `ModListPanel` 现有的 `RowPresentation.TypeLabel` / `ActivationLabel` / `Summary` / `Note`，不修改 `ModListPanel`。

## 4. 老数据部分映射处理（已拍板：自动补齐）

- **纯函数**：在 `ArmorMappingPickerPlanner`（或同模块辅助类）提供 `CompletePartialTwinMappings`：
  - 仅在 `TwinBundlingEnabled` 为 `true` 时生效；
  - 遍历每个孪生组（护甲组、头盔组），若现有映射中已覆盖组内部分成员（`0 < 已映射成员数 < 组内总成员数`）：
    - 选取出现次数最多（并列按组内成员顺序第一个）的视觉来源 `(SourceItemId, ModelKey)`；
    - 把组内其余未映射成员自动补齐到该视觉来源（若老数据极少数情况把同一孪生组拆到了不同来源，也统一对齐到该主来源）；
    - 返回补齐后的映射列表与补齐统计数。
- **调用时机**：在 `ArmorRegistryPageViewModel.ApplySnapshot` 加载快照后执行自动补齐；若发生补齐，更新 `Mappings`、标记 `HasChanges` 并弹提示通知用户「已自动补齐 N 条换色孪生映射（只是颜色不同，游戏里分不开，只能一起换），请点应用保存」。

## 5. 测试计划与交付门

- **单元测试（`HD2ModCore.Tests`）**：
  1. 孪生组判定：非披风布局完全相同才算同一孪生组；`0x…` 未命名记录与拿不到的非玩家记录不进组；民主官 NPC 单列不进组；`B-01` 多布局同名组正确并入孪生组；`AF-02`/`CM-09`、`SA-25`/`B-01` 头盔差异不进组。
  2. 选品器捆绑（方案 A）：护甲/头盔/套装三选项卡合并成一行、标明原因文案、展开全部 `MemberItemIds`；仅头盔孪生的两套护甲独立成套装且 3 槽下互斥、2 槽下只写护甲互不阻塞。
  3. 左侧映射目标合并：同一视觉来源下的孪生目标合并成一行。
  4. 老数据部分映射自动补齐：部分成员已映射时自动补齐整组到同一来源；全映射或未映射时保持不变。
  5. 集中开关：关闭 `TwinBundlingEnabled`（或传 `twinBundlingEnabled: false`）后，恢复原有单独映射、不合并、不自动补齐。
