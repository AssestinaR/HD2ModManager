## #23 UV 整格归位

### 判断

**可合并。** 算法本身我核过，是对的；风险在"机制未证实"和"这是全量几何改动"，
但两者都不阻塞。

### 算法的五条不变量（逐条核过，成立）

1. **按三角形取整格**：`du = -floor((u1+u2+u3)/3)`，三个顶点同量平移 ⇒ 三角形内部插值不变，
   wrap 采样下采样结果不变。这是纯等价变换，"平移"本身不该改变任何画面。
2. **顶点共用按 (顶点, du, dv) 分别占位**：先出现的那个平移量占原下标，其余复制。
   我核了顺序无关性——若先处理"不平移"的三角形，原下标留在原位、平移的那份复制；
   反之亦然。两种情况结果一致。
3. **跨 section 共享顶点**：`assigned` / `claimed` 都是全网格级的，两个 section 用同一个顶点
   加不同平移量时会正确复制。
4. **负格**：`floor(-0.5) = -1` ⇒ 平移 +1，测试用例 `NegativeTile_IsShiftedUp_OnBothAxes` 钉住了。
5. **自身跨度 > 1 的三角形不动**（平铺贴图），只保证"重心那格对"，文档写清楚了。

### 一个我特意核过的耦合

`ExtraBoneSubset.Select(extras, extraBaseCount, mesh)` 是在**归位之后**调的
（`VpkPatchAssembler.cs:684`，归位在 `:666`），但复制出来的顶点带的是**同一份 `Influences`
引用**（`RetargetedVertex` 是 record，`with` 只改 U/V）⇒ 物理骨集合不变，不会因为复制顶点
把某根骨漏掉或重复计入。这条是本 PR 与上一轮"按件切物理骨"的交叉点，没问题。

### 建议（都不阻塞）

1. **加个 A/B 开关。** 这是**默认生效的全量几何改动**，而机制（"U 出格会消失、V 出格不会"）
   作者自己写了"没有查证"。仓库里同类实验性几何/着色改动的惯例是给环境变量退路：
   `SkirtClearance`（`HD2_SKIRT_CLEARANCE`）、`HD2_NO_NORMAL_MAP`、`HD2_NO_MATCAP_LAYER`、
   `HD2_NO_SYNTHETIC_BASE`、`HD2_NO_DRAW`。建议 `HD2_NO_UV_TILE=1` 直接退回原样，
   以后再遇到"某模型归位后反而坏"时有就地退路，不用回滚构建。
2. **PR 描述里"顶点数不变"要改。** 有接缝时顶点数**会涨**（代码自己会报
   `DuplicatedVertices`）。他的实测模型大概没有接缝分裂（Source 的镜像半边本来就是独立顶点），
   所以"不变"在他那台机器上成立，但这句话不能当成普适结论。
3. 逐件 `warnings` 一条：41 件就是 41 行。参照文件里 `normalWired` / `normalMissing` 的既有做法，
   汇总成一行「N 件共 X 个三角形被归位（复制 Y 个接缝顶点）」更省日志预算。
4. 修的是**转换器**：已经导入过的 Mod 要**重新转换**才生效，这条得进 release notes。

## #24 身份 API 探针改回默认关闭

### 判断

**可合并——但这是翻你自己 11-12 定的调，需要你确认。**

`2.1.37` 的注释里写着："2026-11-12 用户定调：有依据的崩溃是正常测试行为；低效率才是真正的坏事。"
所以"默认开启"是当时**有意**的选择，这个 PR 把它翻回来。

我倾向同意合，理由不是"他说得对"，而是**现状已经自相矛盾**：
1.5.16 的调参文件（`%LOCALAPPDATA%\hd2pbx_tune.txt`）里我们已经显式写了 `probeIdentity = 0`
并写进了发布说明。也就是说"我们实际发布的状态"是关，而"代码默认值"是开——
只有改代码默认值，这两者才一致。

### 事实核对

- **触发条件**：`matchedCount > 1`（同款命中多件）。舰船里有人台 ⇒ 人台 + 玩家 = 2 件 ⇒ 会触发。
  这个判据和我们 11-12 的结论（"9 件同款来自分段自定义模型"）完全对得上。
- **崩点日志**（`has_mesh` / `bones` / `World.entities` 各一次）与我们已知的
  "未验证签名 API + 原生 AV 时 `pcall` 拦不住"一致。
- ⚠️ **要分清两条独立的崩因**：11-12 我们定位的真凶是 `refresh_avatar_distances` 读上一帧的
  avatar 句柄（2.1.43 已修）；探针是**另一条**（谁先撞上看运气）。
  所以"修了 `refresh_avatar_distances` 就不用管探针"是错的——这个 PR 有独立价值。
- 他"顺带一提"的第 7 项 `scene_graph_link(unit, 1)` 是**写**接口 —— 我认同，
  建议探针本身也把这一项去掉或挪到最后（这次只是默认关，不代表它安全）。
- guard 用例用 `wholeStripped`（先 `strip_comments` 再匹配），不会被注释里的旧字符串骗成假绿。这一条我核过。

### 一个提醒

关掉之后，**以后想再收集身份判据就得手动改调参文件**。断点续测机制还在，能用；
但如果还想继续做"能不能认出玩家"这条线，建议在 `docs/agent/` 里留一条"怎么开、开之前先看哪份日志"。

## #25 单轴限位 + 驱动心跳（2.1.45）

### 判断

**可合并。** 两个改动都成立，但有一处**注释与代码不符**必须改，否则会误导后来人。

### `gains_of` 的改动是对的

- 只约束一个轴时另一个轴取 ±1（=`sin` 值域上限 ⇒ 分量不夹），
  作者写了约束的轴照旧按原值夹（含单边区间，`axis-asymmetric-test` 里 ⑦⑧ 两组钉住了）。
- 双轴都约束的旧资产行为不变（`axisLimits` 仍为 true，两个轴都有值）。
- 一个轴"flag 有但 lo/hi 都是 0"的情况：`yawSet` 保持 false ⇒ 该轴也不限，
  而原来这种情况下 `axisLimits` 根本没打开 ⇒ 两者等价，没有行为漂移。
- 作用域我核过：`yawMin/yawMax/axisLimits` 在 `:699-700` 声明，新块在 `if flags ~= nil` 分支内，
  没有踩 Lua 5.1 的"读到全局"陷阱。

### ⚠️ 但「总偏角仍由锥兜住」这句话不成立

`physbone_compat.lua:1180` 是：

```lua
if not gains.axisLimits and gains.limit > 0 and dot < gains.cosLimit then
```

**分轴约束的骨根本不走锥**（上面 `:1178` 的注释也写明了"锥是相对父节的，会累加"）。
所以 `flags = 0x35` 这类骨在改后是：**yaw 按作者区间夹、pitch 完全自由、锥不生效**。

这未必是坏事——VRChat 的语义就是"只写了 yaw 限位，pitch 就是自由的"，
作者这么写通常也只是因为"我只想管左右甩"。但 PR 描述和代码注释里那句
"总偏角仍由锥（angleCon）兜住"与实现相反，必须改成"由动力学（刚度/阻尼）兜住，
锥对分轴骨本来就不生效"。否则下一个人会照着这句话去做推理。

如果他**想**让锥成为安全网，那就是另一件事：把 `:1180` 的条件改成
"单轴受限时也走锥"，但那是行为改动，得单独评估（锥是相对父节的、会累加）。

### 心跳改动是对的

- `driveFrames` 每次 `tryAttach` 成功都归零 ⇒ 心跳取模永远打不出来，这个诊断确实废了。
  改成只在安装时归零的 `beatFrames` 是对的，而且 guard 用例把"不许再用 `driveFrames % heartbeat`"
  钉住了（`strip_comments` 之后匹配，不会被注释骗）。
- 顺手核了性能：`tune_values` 有 30 帧缓存（`:1779-1783`），每帧调一次只是查表，
  不会变成每帧读盘。
- 逐链明细改成按件列（每件前 3 条）——理由很实在（"头部那件 17 条链，前 6 条全是单节前发"）。

### 一个脚枪

```lua
local heartbeat = math.max(1, math.floor(tune.heartbeatFrames or options.heartbeatFrames or 600))
```

用户照直觉写 `heartbeatFrames = 0`（想关掉心跳）时：Lua 里 `0` 是真值，`or` 不会跳到 600，
`math.max(1, 0) = 1` ⇒ **每帧一条心跳**，日志瞬间爆炸。建议改成
`local raw = tune.heartbeatFrames; if raw ~= nil and raw <= 0 then return/关 end`
或干脆 `raw > 0 and raw or 600`。

### 版本号

`2.1.43 → 2.1.45`，跳过了 2.1.44（只在注释里）。合并后 `snapshot-test` 也跟着钉在 2.1.45。
如果后面还想自己发版，注意别撞号。
