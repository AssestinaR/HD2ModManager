# VPK 换甲的「头身合并」（2026-11-02）

> ⛔ **状态（2026-11-08）：已退出常规链路。** GUI 的「头身合并到身体」开关已删除（详情页不再提供这个条件），
> 编译基座也不算这个条件；仅 CLI `--head-merge` 保留为实验 / 救急，而且它会把合并**烘进 `sectional/` 本体**
> （协议外产物）。
> 现行链路见 `docs/agent/sectional-compile-base-20261108.md` §4。

> 用户口径：「头盔 unit 中的模型不输出到指定护甲套装的头盔槽位，而是输出到胸部槽位，
> 这样游戏内的头盔 item 就变成了无模型透明的，而护甲自带了头盔。」
> 以及：「并不是强制 1/2，而是看目标护甲有哪些槽位，有可能某些护甲的胸部部位没有 2 层，
> 只有 0/1 —— 我们并不是写死，而是自动地。」

## 1. 解决什么

游戏里护甲与头盔是**两个归档、两个 item**。默认做法把来源的头 Unit 换进头盔归档，
于是玩家**必须**把配套头盔 item 也穿上才有头；换一件别的头盔，头就没了。
而自定义模型的头往往连着身体（发型、发饰、脖子），拆开本来就更不合理。

合并之后：**头跟着护甲走**，那件头盔 item 一件模型都不剩。

## 2. 规则：层号全部算出来，不写死

判定与落点都在 `CliVpkRekey.ResolveHeadBodyMerge`：

| 步骤 | 规则 |
|---|---|
| 头盔套件 | 目标里"件全是 `Helmet`"的那个 |
| 护甲套件 | 目标里有 `Torso` 件的那个 |
| 两者缺一 | 不合并（目标不是"护甲 + 配套头盔"这一对，本来就没有头盔 item 的问题） |
| 可承载层 | 护甲套件胸部槽位里，去掉 `Culling`/`Static`/`Unknown` 后剩下的层 |
| 层数 < 2 | **装不下「身体 + 头」两件几何** → 自动退回老做法，并写一条说明 |
| 层数 ≥ 2 | **最外层放头**、**次外层放身体**，其余层照旧隐藏 |

实测 RE-2310 的胸部槽位只有 `Undergarment` + `Armor` 两层（没有 `Accessory`），
于是：身体 → `Undergarment`，头 → `Armor`。三层（0/1/2）的护甲会得到身体 → `Armor`、头 → `Accessory`。

**为什么头放最外层**：内层会被外层的剔除代理按深度挡掉（2026-11-01 实机结论）。
两件都是我们的几何，说不准谁的代理会挡谁，所以把"一定看得见"的位置留给头——
身体缺一块还能看出是人，头没了整个角色就废了。

## 3. 实现

`CliVpkRekey.BuildPlan` 原来按"部位 × 承载层"一一对应；现在多了一条：护甲套件胸部槽位的
两层由 `(Torso, HeadLayer) → 头 Unit` 与 `(Torso, BodyLayer) → 身体 Unit` 分别占用，
其余层**不给来源**（于是走 `AutoHideUnmappedTargetUnits` 的隐藏壳路径）。
头盔套件直接跳过（一件都不写），它的件同样全部变成隐藏壳。

开关：

- 管理器：**「VPK 动作」卡里的「头身合并到身体」拨动开关**（状态存 `wardrobe.json` 的
  `headMergeIntoBody`，**旧文件没有这个字段 ⇒ 读成 `false`**）。翻转它会**立刻重新生成 Overwrite**
  ——两种状态写出来的 patch 完全不同，只存状态的话用户会看到开关翻了、游戏里却没变。
  已有的「切换」「应用」「重构建」也都按这个开关走，不会把它又打开。
- 命令行：`hd2mod vpk rekey --head-merge on|off`，**默认 off**（只有显式写 `on` 才合并）。

> ⛔ 已过时（2026-11-08）：上面「管理器」那条**已作废**——GUI 的「头身合并到身体」开关已删除，
> 「切换」「应用」「重构建」都改走编译基座，而编译基座不传头身合并（恒 off）；
> `wardrobe.json` 里的 `headMergeIntoBody` 只有读侧还在，常规链路不用它。命令行那条仍然有效。

**为什么默认关**：它是**产物形状**的开关——打开会把头从头盔套件搬进护甲套件的胸部槽位，
并让那件头盔 item 变成空模型。这种改动必须由用户明确选择，不该因为"读到一个没有这条记录的
旧状态文件"就替他启用一个新行为（2026-11-02 用户要求改成默认关）。

### 两个方向都验过：关掉就是精确回退

| 状态 | `9ba626afa44a3aa3.patch_0` | 大小 |
|---|---|---|
| `--head-merge off` | `D9D4727F744A266533B176695DE92F2FFECDF55CDFF61DFB49E8B30F5724E32F` | 599608 |
| 2026-11-01 那版能用的产物（备份） | 同上，**逐字节相同** | 599608 |

## 4. 实测产物（`serenade_bill` → RE-2310）

```
replacedUnits = 12（原来 7）        hiddenMeshes = 44
patch_0     627490 B（原来 599608）  gpu_resources 30265195 B（原来 30265199）
```

| 来源 Unit | 几何 | 落到 |
|---|---|---|
| `2fe1cb63905c0001` | 头（无剔除代理，lod 4…0） | 胸部槽位 **Armor** 层的 4 个目标 unit |
| `2fe1cb63905c0002` | 躯干（自带 lod=-1 代理） | 胸部槽位 **Undergarment** 层的 2 个目标 unit |
| `…0003`–`…0007` | 胯 / 腿 / 臂 | 各部位最外层（与原来一致） |

头盔归档：`af431352d9b95e83` 原来是我们的头（40838 B），现在是 **15000 B 的隐藏壳**
——头盔 item 不再有模型。日志里有一条明确说明：

```
头身合并：头落到 RE-2310 的胸部槽位最外层（Armor）、身体落到次外层（Undergarment）；
RE-2310 的件全部隐藏，于是游戏里那件头盔 item 没有模型，头由护甲自己带着。
```

一个数字值得记：gpu 只差 4 字节（30265199 → 30265195），而头被复制成了 4 份
tenant entry ⇒ 相同 payload 在 gpu 里是共享的，多一份映射不会多一份显存。

## 5. 「开关打开」≠「合并成功」——五种结果都要能说出来

用户提出的问题：目标是**自己的素体**时，section 是照常烘进去的，但头身合并**没有地方可用**
（那个素体本来就是「头 + 身体」一整套，头是它自己的头盔槽件，没有独立的头盔 item 可隐藏）。
如果界面只看开关状态，就会在这种什么都没发生的场合说"已开启"——用户进游戏发现没变化，
就再也信不过这个开关。

所以 `vpk rekey` 的输出里多一个**机器可读**的 `headMerge` 字段，界面照它说话：

| 值 | 含义 | 界面怎么说 |
|---|---|---|
| `applied` | 真的合并了 | 头并进护甲，头盔 item 不再有模型 |
| `off` | 调用方关了 | 头回到头盔套件，要穿配套头盔 |
| `custom-model` | 目标是自己的素体（恒等路径，patch 原样退回 + 烘 section） | 开关已记录，但对当前目标不生效：头本来就在主体里 |
| `single-layer` | 目标护甲胸部只有一层，装不下两件几何 | 开关已记录，但这一次没有合并 |
| `no-helmet-kit` | 目标里没有"护甲 + 配套头盔"这一对 | 开关已记录，但当前目标没有配套头盔归档 |

另外两处配套：

- **卡片上会当场提示**：当下拉里选的是自定义素体时，开关下面直接显示
  「当前目标是自定义素体：头本来就在主体里，这一项对它不生效（换成游戏护甲才会合并）」，
  不用等点了才知道。
- **恒等路径的说明也多了一句**：退回来源时会说"当前没有关掉的 section"或"已把 N 个 section
  烘成关闭"，让"到底做了什么"有据可查。

> ⛔ 已过时（2026-11-08）：上面第一条"卡片上会当场提示"**已作废**——GUI 里没有这个开关了，提示随之消失。
> 上表的 `headMerge` 字段仍是 `vpk rekey` 输出的机器可读值，命令行调用方还能用。

## 6. 风险与待实机验证

1. **身体的层降了一级**（`Armor` → `Undergarment`）。上一轮的"手套/丝袜消失"就发生在
   内衣层——但那是被**目标护甲件**的剔除代理挡住的，而现在胸部两层的目标件都被我们顶掉了，
   代理不存在。`Arm`/`Leg` 等部位仍是外层优先，不受影响。**仍需进游戏确认躯干没缺块。**
2. **换别家头盔会压在上面**：玩家的头盔 item 若不是这套的，那个头盔照常渲染，会穿模。
   这是合并的固有代价（用户已知）。
3. **只有一层的护甲**：自动退回老做法，玩家仍需穿配套头盔。不会静默。
4. 头被复制成 4 份（目标 Armor 层有 4 个 unit，Slim/Stocky 各有两份）。与身体原来的
   多份映射同一机制：引擎只渲染与体型匹配的那一份。

## 7. 验收要点

- 装备 RE-2310 护甲、**头盔 item 留空**（或穿本套头盔）→ 应该能看到头与发型。
- 换一件别家的头盔 → 会盖在我们的头上（预期）。
- 手套、丝袜、袖口仍在（回归检查：这次动了躯干层）。
