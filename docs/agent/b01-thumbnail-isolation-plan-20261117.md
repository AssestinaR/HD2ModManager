# B‑01 头身合并映射与头盔缩略图隔离

## 验收

- B‑01 换色孪生组的 13 条护甲记录都能映射到头身合并的伊莎贝娜。进入游戏穿任一有代表性的受影响版本，角色显示完整模型。
- 打开军需库头盔列表，组外头盔小图保留原版头盔且没有伊莎贝娜的头发。检查保持原版的护甲和离开军需库后的角色。
- 切成未映射的护甲或关闭映射后，角色使用原版外观。换装、退出菜单和世界切换时，旧模型不残留。

## 已知条件

2026-11-17 的游戏内对照中，关闭 Hider 仍能复现串图。只去掉 `293d8135eb95873b` 和 `29b877b122acc704` 指向含头合体模型 `74fa01a11be3f987` 的两条全局链接，小图恢复。现有规划器保护这两个右肩。对本机索引和模组重算，3 条护甲记录能换承载件，10 条缺少合适的承载件。CM-09 的独立手臂承载件限制不属于 B‑01 串图问题。

## 实施顺序

1. 在当前游戏版本核验挂载前提。识别实际穿戴者、确认自定义合体 Unit 在游戏内的资源驻留，并验证生成、骨骼随动和销毁。记录缩略图与实际角色的区分依据。仓库对旧 build 的生成 API 有一次成功和一次闪退记录，需要在当前版本复核。
2. 将缺承载件且原版右肩可识别的头身合并目标交给按实例的运行时路径。规划结果按身形关联原版右肩、需隐藏的原版部件和已部署的模型 Unit。冲突或归属模糊时保持原版。其他目标继续走现有承载件规划。
3. 通过正常的「应用」流程投放规则和运行时。缩略图生成沿用原版右肩。实际角色只有在替换模型已成功挂载后才隐藏对应原版部件。换装、关闭映射和世界切换清理模型并恢复原版可见性。仅在有已验证的隔离依据时接入右侧大预览。
4. 核对 13 条真实记录的规划结果、链接输出、按实例规则与无冲突行为。执行 Lua 生命周期测试、`dotnet build -c Debug`、`dotnet test -c Debug` 和游戏内验收。

## 资产对照

- 原版玩家 Avatar 有 107 个 TransformInfo 节点。伊莎贝娜的两个含头 Unit 都有 156 个节点。按名称哈希对照，合体 Unit 覆盖全部 107 个原版节点，只有 5 个节点的下标恰好相同。实机挂载必须使用两边分别解析的下标。
- 现有映射中，TR-117「阿尔法指挥官」会通过正常换装路径生成同一个合体 Unit。可用它确认当前版本的资源驻留和实例生成，再验证身上只穿 B‑01 时也能加载该 Unit。
- 实机预检从主世界读取了身穿 TR-117 的玩家及其已生成的伊莎贝娜 Unit。在主世界生成第二份 Unit，确认资源 ID、156 个节点和 107 次骨骼链接，并成功销毁测试实例。军需库的右侧预览和小图批次同在另一个世界。主世界生成和销毁测试实例时，军需库世界的 Unit 数量没有变化。

## 验证记录

- 用本机安装的索引、模组和当前映射重算，B‑01 组 13 条护甲与 19 条头盔记录均有映射结果。生成两条按身形区分的实例规则，未生成指向该合体模型的全局右肩链接，且没有链接冲突。
- Lua 测试覆盖资源未可用、实例生成和链接、重复更新、原部件恢复、预览世界隔离、主世界切换与链接失败。真实数据重算也确认使用这对右肩的孪生记录不会同时走全局替换。
- `dotnet build -c Debug` 通过（0 警告、0 错误），`dotnet test -c Debug` 通过（2524 通过、1 跳过）。冷启动日志确认读取了两条实例规则，71 条全局覆盖全部注册成功。游戏界面验证结束前恢复了原配置并移除了临时补丁，B‑01 实际穿戴与缩略图的端到端检查留给体验版。
