# 民主官 NPC：护甲 + 头（头身合并）规划（2026-11-16）

## 1. 目标（用户原话要点）

- 什么 Mod 都不额外装，把民主官 NPC 映射到某套 Mod 护甲，他就变成 Mod 护甲的民主官（身体、手臂、**头**都是 Mod 的）。
- 具体做法参考「爱弥斯民主官」Mod。用户选定路线：**头身合并**（2026-11-16）。

## 3. 方案

**核心规则：只有模型的头真的会显示时，才把民主官的脸藏掉。** 否则会得到一个没有头的民主官（上一版无条件藏脸的副作用）。

1. **低污染映射**（用户在用的）：
   - 素体是两槽（头身合并）：隐藏集 = 目标部件 + 同套头盔部件 + **民主官的脸**；预览写明「头已并进身体，民主官的脸会隐藏」。
   - 素体是三槽：脸**不藏**，民主官保持原版的脸；预览写明「民主官没有头盔，三槽下模型的头显示不出来；想要模型的头，在 Mod 详情页打开头身合并」。
2. **专属切换**（`SectionalExclusivePlanner`）：头身合并生效（`mergeActive`）时才加脸；否则不加。
3. **转专属**（`KitConversionPlanner`，爱弥斯这类自带头的 Mod）：Mod 覆盖了脸单位的任何一个材质（作者本来就在藏/换脸）才加脸；Mod 没碰脸就不动它。
4. 常量：`KitNonPlayerArmors.DemocracyOfficerFaceUnitId` / `DemocracyOfficerFaceMaterialIds` / `ExtraHideUnits`。

## 4. 不做的事

- 不做「虚拟头盔」（把脸单位当头盔、头直接覆盖到 `7862870b` 上）：脸单位是 NPC 的骨架，头模型要重新绑定，覆盖又是全局的。等头身合并验证后再评估。
- 不改压缩计划、不新增压缩 unit：三槽素体想让民主官有头，只能打开头身合并（与其它护甲的头盔映射互斥，既有行为）。

## 5. 验收

- 单测：两槽映射民主官 → 隐藏集含脸；三槽 → 不含；玩家 FS-05 任何情况都不含；专属切换头身合并开/关；转专属覆盖脸材质 / 不覆盖。
- 全量 `dotnet test -c Debug`、`dotnet build -c Debug` 0 警告 0 错误。
- 实机（待用户）：把一个头身合并的 Mod 映射到民主官 → 进飞船看到 Mod 的头、原版脸不见；换三槽 Mod → 原版脸还在。

## 6. 与用户对话核对

- 「现在民主官没有头」= 脸被无条件隐藏 + 三槽素体没有头可显示（已对上）。
- 「改成护甲+头盔」按用户选定的「头身合并」实现：头跟身体合成一个承载件，不是单独的头盔行。

## 7. 补充（2026-11-16，用户：「这个应该是不允许分离的，只能一套」）

- 民主官 NPC 只在选品器的「套装」页出现一行（类型「护甲+头」），**不再出现在「护甲」页**：他没有头盔，护甲和头不能分开。
- 三槽素体（已编译、无头身合并）打开时，这一行置灰，原因「民主官的头必须并进身体：这个素体是三槽，请先在 Mod 详情页打开『头身合并』」；两槽素体、没打开素体、未编译（读不到布局）时可选。判定用 `IsThreeSlotCompressedCustomModel`，只认**已编译出的布局文件**，没构建过的 Mod 不误拦。
- 左侧已映射列表的合并投影不变（他仍单独成行并带「民主官 NPC」标签）。

## 8. 补充（2026-11-16）：女舰长 / 维修技术员（只记事实，未做映射）

- 「守岸人 替换 女舰长」只有 1 个 unit `d87d04aacbc0269c`（女军官根 unit，原版是 47KB 无几何的空壳，Mod 往里填一个约 16.5 万面、1 个材质、149 张贴图的整身模型，gpu_resources 约 355MB）+ 41 个材质（36 个覆盖原版）。**它不复用护甲，自带整套模型。**
- 它「隐藏」靠把约 31 个 NPC 头部 unit（归档 `fc5b6bff0db90aab`，无几何）的材质换成空壳，所以所有 NPC 的脸一起消失（民主官、维修技术员都中招）。31 个候选 ID 见 `kit_instance_hider.lua` 的 `HEAD_CANDIDATES`。
- 实机确认（Hider 0.4.5 探针）：女舰长的头 `85d4ba84db7d27e5`（到根 unit 距离 0.00、4 实例）；维修技术员的脸 `4d4017549585cb8e`（站在他旁边 0.94 米时最近的候选）；民主官的脸 `7862870bc9822eeb`。
- 女舰长骨架 69 根，玩家 90 根：玩家护甲的压缩模型不能直接挂到她身上，要映射别的护甲给她必须重定向。她没有护甲记录，所以现有映射（承载件链接）管不到，也没有「用一套护甲省资源」的路径。
- 转专属功能已被用户删除（逻辑已迁到映射），这里不再依赖它。
- **2026-11-16 实现（「硬来」）**：女舰长（根 unit `d87d04aacbc0269c`，脸 `85d4ba84db7d27e5`）和维修技术员（根 unit `93fb8680b7ff7f96`，脸 `4d4017549585cb8e`）作为 NPC 伪护甲记录（`KitNpcRecords`，ID `0xFEED0001/2`，唯一的部件 = 根 unit）接进映射：`ArmorAuthorityIndexReader` 追加伪 kit、选品器目录追加伪条目；选品器里和民主官同规则（只在「套装」页、名字带标注、三槽置灰）；映射规划 `PlanNpc`：根 unit 当承载件链接到素体头身合并躯干 unit，脸按实例隐藏（Hider 规则 `lp-<id>` 锚点 = 根 unit）。技术员的根 unit 来自「2B Technician Replacer」补丁（它覆盖 13 个 unit，其中 12 个是 NPC 头部，93fb8680… 是和 d87d… 同形的无几何空壳，实机也出现在技术员旁边）。
- 取舍：NPC 用自己的骨架（女舰长 69 根 vs 玩家 90 根），不做重定向，模型可能变形或不动；运行时 wardrobe.links 对 NPC 根 unit 是否生效未实机验证。
- **2026-11-17 站姿修正**：首版实机两个 NPC 都是 T 字站姿——玩家护甲压缩 unit 的 TocData 头部 `0x08`（骨架引用）是 0，顶替 NPC 根 unit 后 NPC 动画驱动不了它。对照「守岸人」补丁里的 d87d 和原版 d87d 的头部：`0x08` = NPC 骨架 `b5c27e4a810df382`（女舰长、技术员共用，69 根骨，命名和玩家同一套），`0x10`（原版 `ddf83b89…`）被 Mod 清成 0，`0x20` 原样保留。做法：低污染编译（头身合并）给每个 NPC 写一份合体 unit 的副本，TocData 头部补成上面三个字段，网格 / GPU 字节不动（写入侧按内容去重），layout 里加角色 `npc-<item>`；映射优先链这个副本。旧产物的 layout 没有它，`LowPollutionFreshness.MissesNpcVariants` 判过期，应用时自动重编一次。真实素体（Urara）编译测试通过；站姿是否正常要实机确认。
