# 整合包：按「模型主体」分组转换（2026-11-02）

> 起因：用户的 292 MB 中文整合包里有**几套不同角色**（本样本 3 套：chiffon 长发 / chiffon 短发 / plum），
> 每套都是完整八人包；而且包内文件夹又深又长，导入直接失败。
> 目标：导入后库里看到的是 **3 个主体**，每个主体下挂**它自己的**材质选项组。

## 1. 为什么必须分组

两件事叠在一起：

1. **材质裸名跨角色撞名**。chiffon 的是 `materials/ko_chiffon_aw/tights_socks`，plum 的是
   `materials/ko_plum_aw/tights_socks` —— `SourceMaterialSource` 按**裸名**索引、先到先得，
   整批一份解析集合的话，chiffon 的模型会吃到 plum 的材质。
2. **材质 id 只在同一命名空间内唯一**。整批一个命名空间，两套角色的同名材质就是同一批 id，
   装在一起互相覆盖；分成两个命名空间才能共存（代价是同一份材质会被转两次）。

## 2. 归属判据：内容，不看文件名

| 侧 | 拿什么 | 例子 |
|---|---|---|
| 模型 | mdl 里声明的材质**目录**（cdtexture 串，以分隔符结尾） | `ko_chiffon_aw\`、`ko_chiffon_aw\switch\` |
| 材质包 | 它提供的 **VMT/VTF 目录** | `materials/ko_chiffon_aw` → `ko_chiffon_aw` |

目录有交集 ⇒ 它是这个模型的材质包；一个包可同属多个模型（短发共用长发的材质就是这样）；
**对不上任何模型就跳过并点名**，不回退、不猜。

> 为什么不用文件名前缀：作者习惯一变就系统性判错；而两侧本来就各自写着"我要哪些目录的材质"。
> 为什么连 VTF 也算：实测有包只带一张 `warp.vtf`（卡通渐变条）就构成一个渲染风格选项，一个 VMT 都没有。
>
> mdL 目录是扫字符串拿的（以分隔符结尾的可打印串），不走版本相关的结构解析：
> 读坏了最多是"读不出目录"，不会读错。

## 3. 三个必须一起处理的坑

### 3.1 带模型的材质包

「基础材质」= 78 个 VMT + 27 个 VTF + **5 个 mdl**（`ko_chiffon_aw/3`、`/1`、`anims_survivor_def_ragdoll`…），
其中一个 mdl 骨骼数是 0。它先被判成"模型"、再因为模型读不出来被判成"不支持"——
而它其实是整只角色的**主材质**。判据：只要它提供的材质目录对得上某个模型，整包改判成材质包，
内部模型当附属内容忽略。

### 3.2 转换器不能自己再猜一次类型

「有 `.mdl` 就当角色」这条在转换阶段同样会炸（`MDL 骨骼数量异常：0`），
而且报给用户的是一句"这个 VPK 里没有 HD2 能用的资源"，完全看不出原因。
新增 `--treat-as model|material`：规划阶段已经知道答案，显式传下去。

### 3.3 组里只留"真正可转换"的材质包

判据"提供了同名目录"只回答"属于谁"，**不等于**"值得转"。组件开关包（`附加材质X关`）和
"只换渲染参数"的变体（`组件材质b1/b2/b3/c2`）同样提供同名目录，留在组里就会多转出一堆
没意义的选项 Mod（实机第一次就是这么翻车的）。

## 4. 两道路径墙

| 墙 | 现象 | 修法 |
|---|---|---|
| 解压后绝对路径 **268 字符** | 临时根就占 105（`%TEMP%\hd2modmanager-vpk2patch\<32位>\source\`），叠上包内 212 的嵌套 > 260 | **摊平解压**（`7z e`）+ 短临时根 `%TEMP%\h2v\<8位>`，最深降到 ~90。摊平前检查包内同名 VPK，有就退回结构化解压 |
| 命令行 **32767 字符** | 140 个 VPK 的绝对路径近 3 万字符，`CreateProcess` 直接失败，报「文件名或扩展名太长」（Win32 206）——看着像路径太深 | 新增 `--vpk-list` / `--material-source-list` / `--component-source-list` 清单文件 |

## 5. 非角色包不排进转换队列

路径快筛（`models/props*`、`anims_*`、`models/weapons/*`、特效、碎块）+ 转换时的骨架校验
（后者本来就有）。**不限定只认生还者**：敌人模型只要骨架合适照样是角色。
本样本 33 个道具/手模、2 个动画包被正确跳过。

## 6. 选项关系按主体挂

转换结果带 `VpkProducedPackage(Directory, GroupName, IsModel)`，导入后只把**同一组**的材质
挂给该主体——否则 chiffon 下面会出现一堆点开什么都不变的 plum 材质。

## 7. 实测（该整合包 140 个 VPK）

```
规划：convertible=13（3 模型 + 10 材质）  groups=3  unassigned=0
【chiffon 绀碧之翼 2.1 飞行员】      材质选项 5（基础材质 / a1 / a2 / c1 / 预设材质）
【chiffon 绀碧之翼 2.1-短发 飞行员】 同上 5（共用 chiffon 的材质文件，但独立命名空间）
【plum 绀碧之翼 2.1 飞行员】         同上 5

单模型转换 10 秒（7 Unit、components.json 22 个开关 / 54 块几何）
基础材质转换 29 秒（17 材质 / 17 贴图）
命名空间隔离：同一份「组件材质c1」在两个主体下材质 id 交集 = 0
```

## 8. 还没做的

- **互斥组**：`基础材质` 与 `预设材质` 在源包是"二选一"，但它们用同一批材质 id，
  同时启用会互相覆盖。管理器目前把两者都列成可启用选项，要彻底解决得给选项加"互斥组"标记。
- `组件材质b1/b2/b3/c2`（换渲染参数）若要支持，同样得走"替换版本 + 互斥组"，而不是独立材质包。
- 该包的贴图有两个源侧问题会照实报：`face_eyes_phong`（占位底色、无 matcap 兜底）、
  `headphonespulse_alpha`（`tex_pulse_flipbook_123` 的 mip0 尺寸与头不符）。
