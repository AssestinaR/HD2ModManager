# 按实例隔离共用部件：计划

日期：2026-11-13
接续：[护甲串件隔离交接](armor-shared-unit-isolation-handoff-20261113.md)

## 1. 问题

两套护甲引用同一个原版 Unit。软映射调用 `Application.set_resource_override('unit', 源, 目标)`，它按 Unit ID 全局生效，所以 A 改了，B 也跟着变。[当前软映射](../../HD2RuntimeArmorOverride/src/armor_override_runtime.lua#L142)

现实案例：Mod「爱弥斯民主官」想隐藏 FS-05 神射手的原版身体，只能全局覆盖 9 个身体材质。CE-64、CM-17、FS-11、FS-61、B-24 和 FS-05 共用这些身体部件，于是一起丢了身体。

已排除的路线：

| 路线 | 为什么不走 |
|---|---|
| 改 `generated_customization_armor_sets.dl_bin` 让 A 引用新 Unit | 反作弊拒绝被改过的内容，见[真映射交接](true-mapping-next-steps-handoff-20261113.md) |
| 旧 FFI 运行时改内存中的注册表根指针 | 当前引擎版本没有 ffi 模块，且超出允许的 API 清单 |
| 只用资产补丁 | 补丁只能按资源 ID 替换，同一个 ID 无法区分 A 和 B |

## 2. 新路线：不改资源，只改场上的实例

允许清单（`hd2pbx_api.txt`）中有只作用于单个实例的调用：

| 用途 | 调用 |
|---|---|
| 找出场上所有玩家 | `World.units_by_resource(world, 'content/fac_helldivers/cha_avatar/avatar_helldiver')` |
| 列出部件实例 | `Application.worlds()`、`World.units(world)`、`Unit.alive(unit)` |
| 读部件的资源 ID | `Unit.resource_name(unit)`，用 Lua 自带的 `tostring` 转成文本后取出 16 位 hex |
| 判断部件属于谁 | `Unit.world_position(unit, 1)`，离哪个玩家最近就归谁 |
| 隐藏或换皮（第 3 阶段才用） | `Unit.set_unit_visibility`、`Unit.set_mesh_visibility`、`Unit.set_material` |

找玩家和按距离归属的写法，管理器自带的物理运行时已经在用，见 `HD2PhysBoneCompat/src/physbone_runtime.lua` 的 `findAvatars` 与 `discover`。2026-09-26 的移动实验也看到，同一个角色身上的护甲部件根节点坐标相同，并且一起移动。[空间预检](../../HD2RuntimeArmorOverride/notes/refresh-spatial-preflight-20260926.md)

### 怎么认出穿 A 套的人

只要某个玩家身上出现了 **A 套独有的部件**（下称「标记部件」），就认定他穿的是 A。然后只处理这个玩家身上属于 A 套的那些共用部件，穿 B 套的人不受影响。

游戏数据索引中，138 套身体护甲有 107 套至少有一个独有部件，可以这样识别。另外 31 套没有独有部件，本方案覆盖不到，需要明确列给用户看。

### 首个 A/B 对照

| 角色 | 护甲 | item id | 说明 |
|---|---|---|---|
| A | FS-05 神射手 | `124623533` | 标记部件为 slot 8 左肩 `82595b5d94c57343`，只有这一套使用。爱弥斯模型就装在它上面 |
| B | CE-64 | `1732669856` | 与 A 共用腿（slot 4、5）、胯（slot 3）、胸（slot 2 的 piece_type 1）、臂（slot 6、7 的 piece_type 1）等部件 |

完整部件表见探针源码中的 `WATCH` 表，数据由 `asset-index.sqlite` 的 `game_data_authority_pieces` 导出。

## 3. 分阶段

### 阶段 1：只读探针（本轮）

源码为 `HD2RuntimeArmorOverride/src/kit_instance_probe.lua`。它以 Lua mod 的形式由 MDL3 加载器加载，只读不写：

- 约每秒扫一次。找出所有玩家，再找出 `WATCH` 表里的部件实例，记录资源 ID、根坐标、最近的玩家和距离。
- 对每个玩家判断身上有没有标记部件，以及能不能凑出 FS-05 或 CE-64 的完整部件集合。
- 另外按根坐标相同来聚类，覆盖军械库预览里没有玩家 avatar 的情况。
- 只在结果变化时写一行日志，日志有大小上限。
- 不调用任何 `set_*`、`spawn`、`destroy`、`link`。

**要回答的问题与判据：**

| # | 问题 | 判据 |
|---|---|---|
| Q1 | 能否稳定读出部件的 16 位资源 ID | 每次快照中，`WATCH` 命中的部件都能解析，无 `unresolved` |
| Q2 | 在飞船上穿 A，能否把 A 的部件全部归到自己名下 | 自己名下有标记部件，并且 FS-05 的身体部件距离都小于 0.5 米 |
| Q3 | 打开军械库预览时，预览模型在哪个 world，能否按坐标聚成一组 | 出现一个含标记部件的坐标簇 |
| Q4 | 换到 B，再换回 A，结果是否跟着变 | 自己名下的判断依次为 A、B、A |
| Q5 | 任务中有队友时，归属是否会串 | 每个玩家名下的部件各自成套，没有一个部件同时离两个人都很近（距离差小于 0.3 米时记为歧义） |
| Q6 | 每次扫描的耗时 | 日志中的单次扫描耗时，目标低于 2 毫秒 |

**产物与上机步骤：**

- 源码：`HD2RuntimeArmorOverride/src/kit_instance_probe.lua`，资源名 `mods/hd2modmanager/kit_instance_probe`。
- 离线测试：`HD2RuntimeArmorOverride/tests/test_kit_instance_probe.lua`，用假引擎验证解析、归属和聚类，并在调用清单外的 API 时直接报错。需要 LuaJIT 才能运行。
- 打包：`python HD2RuntimeArmorOverride/scripts/build_lua_mod.py --lua <源码> --resource mods/hd2modmanager/kit_instance_probe --out .local-notes/kit-isolation/KitInstanceProbe-0.3.0.zip ...`。`.local-notes/` 不进 git。
- 日志：`%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\KitInstanceProbe.log`，上限 2 MB。

用户上机按这个顺序操作，每步停 5 秒左右：

1. 在管理器导入 zip 并启用，部署后启动游戏，进入飞船。
2. 穿 FS-05，站着不动。（Q2）
3. 打开军械库预览 FS-05，然后关闭。（Q3）
4. 换 CE-64，再换回 FS-05。（Q4）
5. 有条件的话，进一局有队友的任务。（Q5）
6. 退出游戏，把日志发回来。用完在管理器里停用并移除探针。

### 阶段 2：判断是否继续

- Q1 至 Q4 都通过：进入阶段 3。
- Q5 不通过：阶段 3 先只在飞船和军械库生效，任务中不处理，并在界面上说明。
- Q1 或 Q2 不通过：此路线不可行，在本文记录原因后停下，不做阶段 3。

**阶段 1 结论（2026-11-13，记录 3、4）：** Q1、Q2、Q3、Q4、Q6 通过。Q5（队友）尚未实测。爱弥斯这个案例只需要处理民主官 NPC，判定不依赖玩家归属，所以 Q5 不阻塞它。

### 阶段 3：隐藏与验收（2026-11-13 用户同意后开始）

**已做（第一版，规则写死在运行时里，尚未接入管理器协议）：**

1. **核对隐藏范围。** 从游戏数据导出 `124623533` 的全部 Unit，读出绑定的材质，再和原 Mod 的 9 个隐藏材质对照。结果：slot 2 至 7 和 slot 9 的 20 个部件都至少绑定一个隐藏材质；披风 `ea846ef4` 一个都没绑定，所以原 Mod 本来就没藏披风。原版 `82595b5d` 绑定的两个隐藏材质（`391170e7`、`9ca177fe`）不受影响，因为 Mod 自带的 `82595b5d` 只绑定 5 个新材质。
2. **运行时** `HD2RuntimeArmorOverride/src/kit_instance_hider.lua`，资源名 `mods/hd2modmanager/kit_instance_hider`。
   - 每 0.5 秒扫描一轮，每帧最多 300 个 unit。
   - 找到 `82595b5d` 后，对根坐标与它相距 0.3 米以内、并且在那 20 个 ID 里的实例调用 `Unit.set_unit_visibility(unit, false)`。
   - 标记的位置取本轮和上一轮的结果，所以排在标记前面扫到的部件，最晚在下一轮（0.5 秒后）隐藏。
   - 连续 10 次隐藏失败就停手，并写一行日志。
   - 日志写到 `Logs/KitInstanceHider.log`，只在数量变化时写，记录 `markers`、`hidden`、`left_visible`。
   - 离线测试 `tests/test_kit_instance_hider.lua` 覆盖以下情况：只藏民主官；玩家、预览、爱弥斯本体和披风都不动；不碰已销毁的 unit；标记消失后不再隐藏；隐藏失败后停手。
3. **爱弥斯 Mod** 去掉 9 个全局隐藏材质，以及只被它们引用的 3 张贴图，剩下 36 项：1 个 unit、5 个材质、30 张贴图。`.stream` 变为 0 字节，原来那两张带流数据的贴图只被隐藏材质引用。库内文件已用新文件替换，SHA-256 与产物一致；部署进游戏要等用户点「切换」。
4. 打包为 `.local-notes/kit-isolation/KitInstanceHider-0.1.0.zip`，zip 内容与源码一致。

**上机验收：**

| 操作 | 预期 |
|---|---|
| 管理器导入 Hider zip，停用探针，点「切换」，重启游戏，进飞船 | 民主官只显示爱弥斯和披风，没有原版身体；日志中 `markers` 至少为 1，`hidden` 约为 14 至 20 |
| 自己穿神射手（`3970674111`），打开军械库并转一圈 | 身体完整，不缺胳膊腿 |
| 换 CE-64、CM-17、FS-11、FS-61、B-24 | 身体完整 |
| 回到飞船走近民主官 | 民主官仍是爱弥斯；自己不站进他身体里时，身上部件不受影响 |
| 停用 Hider，再点「切换」并重启 | 民主官露出原版身体（说明是运行时在起作用） |

**已知限制：** 刚进飞船的头 0.5 秒左右，民主官可能闪现原版身体。如果站到距民主官根坐标 0.3 米以内，自己的共用部件也会被藏。目前规则写死在 Lua 里；要推广到任意 Mod，还需要管理器写出规则文件。

1. 在运行时中加一个「按实例隐藏」模块，规则来自管理器写出的协议，例如「穿 FS-05 时，隐藏这些部件」。
2. 用 `set_unit_visibility(unit, false)` 隐藏 A 身上的共用部件。部件重新生成（打开军械库、进入任务）后要重新应用。
3. 爱弥斯 Mod 去掉那 9 个全局隐藏材质，改由运行时只隐藏 FS-05 身上的身体部件。
4. 按交接文档的验收表做 A/B/A 对照，再加一行：「穿 CE-64、CM-17、FS-11、FS-61、B-24 时身体完整」。

## 4. 风险与未知

- **允许清单之外的调用。** `IdString64` 不在清单的命名空间里，探针不使用它。资源 ID 从 `Unit.resource_name` 的 `tostring` 文本中解析，依据见实验记录第 2 行。日志用 MDL3 加载器提供的 `open_log` 写，不直接调用 `io`。计时用 `Application.time_since_launch`，单帧耗时在 `os.clock` 存在时用它，与物理运行时相同。
- **隐藏会不会闪一下。** 部件重新生成后要到下一次扫描才会隐藏，可能有一两帧露出原版。阶段 1 只记录部件生成后多久被扫到，阶段 3 再评估。
- **隐藏后的影响。** 隐藏只影响显示，不改件记录，因此按设计不改变护甲值。阶段 3 的验收仍要实测确认。
- **对局里别人看到什么。** 运行时只改本机的显示，队友看到的仍是原样。这和资产补丁的效果相同。
