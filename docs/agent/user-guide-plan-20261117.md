## 2. 第一期三篇

### 教程 1：安装一个普通的绝地潜兵 2 Mod（直接替换护甲）

适合：只想把 Nexus 等处下载的 HD2 护甲 Mod 装上。

步骤（按当前界面）：
1. 首次使用：设置 → 「游戏与资产」确认**游戏目录**、**Mod 库目录**正确。
2. 把 Mod 的压缩包或文件夹**拖进管理器**（或点"导入"）。
3. 在模组库里找到它，**加入活动配置并启用**。
   - 设置 → 通用 里有「导入 Mod 后自动加入活动配置并部署」，打开后这一步自动完成。
4. **部署**，进游戏查看效果。

必须讲清的缺点（**污染**）：原版 Mod 是直接替换某件原版护甲的模型，
所以凡是共用这些部件的护甲/其他玩家看到的同件护甲都会一起变。想要"只换我指定的那一件"，看教程 2。

### 教程 2：把 Mod 转成素体，再映射到你想要的护甲（低污染）

适合：想把某个 Mod 的外观穿到**指定**护甲上，并尽量不影响其他护甲。

前提：教程 1 的第 1、2 步（Mod 已在库里）。

步骤：
1. **一次性设置**（设置页）：
   1. 「内置 lua」→ 打开「启用管理器内置 lua 类功能」。
   2. 「映射模式」选「独占 boot」（或已装外置加载器时选「外置加载器兼容」）。**默认是「关闭」，不改则映射不生效。**
   3. 打开「低污染模式」（**推荐**）。
2. **转成素体**：打开该 Mod 的详情页 → 顶部动作「**生成sectional版**」→ 底栏里填名称、选护甲来源（和/或头盔来源，不要的选「不包含」）→ 「生成」。生成后会作为新条目自动进库。
   - 注：界面上以前叫"只转自定义素体"，现已合并进「生成sectional版」。教程里统一写"转成素体（生成sectional版）"。
3. **映射**：打开护甲映射页 → 左侧选刚生成的素体 → 右侧挑要换外观的目标护甲 → 打开「启用映射」→ 点「**应用**」。应用完成后会自动部署。
4. 进游戏，穿上目标护甲确认。

必须讲清：
- 低污染模式**只在点「应用」时生效**；开关本身不做任何事。
- 不开低污染：仍然能映射，但共用部件会一起被换，**有污染**。
- 低污染依赖内置 Lua；映射模式为「关闭」时开了也无效（设置页会有提示）。

### 教程 3：导入求生之路 2（L4D2）的人物 Mod

适合：想把 L4D2 的人物模型穿到 HD2 护甲上。

L4D2 人物 Mod 的常见结构（给用户的"整理一下再拖进来"说明）：
- **人物模型 VPK**：一个包通常替换 8 个幸存者中的某一个（或多个版本）。**只需要挑你想要的那一个人**。
- **材质 VPK**：换色/换皮肤，管理器导入后会变成这个 Mod 的**可配置选项**。
- 准备：把「选中的人物 VPK + 它的材质 VPK + 可选项 VPK」放进**同一个文件夹**（压缩包也可以），整个拖进管理器。

步骤：
1. 按上面整理好文件夹，拖进管理器。管理器识别到 VPK，会自动走 VPK 导入，转换产物作为**自定义素体**入库（不会替换任何原版护甲）。
2. 后续与**教程 2 的第 3 步**完全一样：去护甲映射页映射到目标护甲、应用。
   （VPK 导入出来的已经是素体，**不需要**再点「生成sectional版」。）

需要在截图时核实的点（写之前用真实包走一遍）：
- 一个包里 8 个人都在时，是导入时让选，还是需要用户自己先挑出来。
- 材质 VPK 变成选项后，选项在 Mod 详情页的哪里开关。

## 3. 页面形式（简单为主）

- 一篇教程一个 HTML 页面，加一个 `index.html` 目录页。共用一个 `guide.css` 和一个 `guide.js`，不需要构建步骤。
- 每篇固定结构：**适合谁 → 前提 → 步骤（每步一张截图）→ 怎么确认成功 → 常见问题**。
- 交互只做三样：
  1. 截图上的**编号标注**，点击编号显示说明；
  2. 截图**点击放大**；
  3. 步骤**上一步/下一步**（同时保留整页滚动阅读）。
- 截图命名：`<教程id>-<步骤号>.png`，例如 `t2-03.png`。

## 5. 跟随版本更新的机制

每篇页面的 `<article>` 上写：

```html
<article id="body-mapping" data-verified="1.5.18"
         data-sources="ArmorRegistryPageView*;SettingsPageView*;ModDetailsPageViewModel.Actions*">
```

- `data-verified`：最后一次对照真实界面核对的版本。
- `data-sources`：这篇依赖的界面/代码文件。
- 发版前跑一个小脚本：读这些属性 + `git diff <上个tag>..HEAD --name-only`，列出"依赖文件变了但没重新核对"的教程。脚本放 `tools/`，第一期可以先手动跑，不进测试。
