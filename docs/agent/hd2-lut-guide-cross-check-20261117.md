## 1. 文档确立的材质结构（我们此前没有完整认识）

### 1.1 LUT 材质 = 查表

```
ID Mask（RGBA，两个 square array 叠成 DDS）
    ↓ 每个通道 = 一行
Primary LUT（23 列 × 8 行，.EXR/.DDS，值可负、可 >1）
    ↓ 每列 = 一个效果
最终颜色 = LUT 列 1 的 RGB × ID Mask 通道 + 各种叠加
```

- 行 1–4 = ID Mask 数组 1 的 R/G/B/A；行 5–8 = 数组 2。
- 关键列（与我们的需求相关）：
  | 列 | 作用 |
  |---|---|
  | 1 | RGB = **主色**；Alpha=1 激活列 13、关闭列 14；Alpha=4 同上并换用 composite detail 图 |
  | 2 | R：bump 强度[0..25]；G：bump R&G 强度[0..10]；B/A：列 4/5 的"应用反转" |
  | 11 | R：**粗糙度[0..10]**；B：边缘提亮（需列 1 alpha = 2/3） |
  | 14 | R：**自发光强度[0.001..0.06]**，0 = 关闭 |
  | 15 | 受光染色（建议保持 0） |

### 1.2 贴图通道约定

| 贴图 | 通道含义 |
|---|---|
| Normal/Curvature | R/G = 法线，**B = 环境光遮蔽**，**A = 曲率** |
| ID Mask | R/G/B/A = 四个遮罩通道（BC7 **sRGB** DX11+，DX10 头） |
| Albedo（`advanced` 族槽 5） | RGB = 底色，**A = 自发光** |

### 1.3 自发光

- 由列 14 的 R 值开启（>0.001）。
- **强度受粗糙度调制**：粗糙度 0 最强，粗糙度 0.9 明显变弱（文档给了对照图）。
- 会让主色、decal、pattern、Mask 1 发光；Mask 2/3 不受影响。
- decal 与 pattern **不受粗糙度影响**，恒定发光。

## 2. 与我们的实测对照

| 文档说法 | 我们的实测 | 结论 |
|---|---|---|
| 贴图按 sRGB 存（ID Mask 要求 BC7 **sRGB**） | 灰阶拟合 `输出 = 0.2580 × 反照率 − 0.0066`，**R²=0.9926、截距≈0** | ✅ 一致：一次解码 + 一次编码，无重复 gamma |
| **舰内与任务中光照不同，不同星球也不同** | gain=0.258 是在舰内量的；同一张卡在不同场景必然变 | ✅ 一致：gain 属场景，必须分场景标定 |
| Blender 的 Accurate Shader **不是 100% 准确** | 我们的 numpy 预览器同样只能做到近似 | ✅ 官方也承认"外部模拟器有偏差" |
| AO 在**军械库界面不生效** | 我们的测量全在舰内（军械库环境） | ⚠️ 提醒：舰内量到的 AO 项不代表任务内表现 |
| 法线贴图 **A = 曲率**，B = AO | 我们把法线槽换成平贴图后画面变"平" | ✅ 一致：等于 AO=1、曲率=0，细节全丢 |
| `advanced` 族 11 槽：2=Nar（A=粗糙度）、3=IlluminateData（金属）、5=AlbedoEmissive（A=自发光） | 我们的材质正好 11 槽，槽 3 指向 16 B（4×4）小图 | ✅ 一致：槽位结构对得上 |

## 3. 文档**纠正**了我此前的一个判断

我原以为"绝对值只能靠不受光材质（改 shader）"。文档给出两条更正规的路：

1. **`original` 模板有独立 `EmissiveColor` 槽（槽 1）**，`advanced` 族没有，靠底色 A 通道。
2. **LUT 材质的自发光在列 14**，且强度受粗糙度调制。

但两条**都不能直接当绝对探针**：

- 自发光强度是"档位"（0.001~0.06），不是物理量，映射未知；
- 自发光仍然会和受光项相加，再一起过 tonemap；
- 列 14 只存在于真 LUT 材质里，我们这块板用的 `advanced` 族没有 LUT。

⇒ **结论：绝对标定仍要靠"两个不同光照环境"把 gain 与 tonemap 分离**，
而不是靠自发光。自发光最多用来定性验证"自发光是否绕过光照"。

1. **保留 12 格密集色卡**（已部署），舰内量第一组。
2. **进任务再量第二组**（文档明确舰内≠任务，这正好是我们的实验条件）。
3. 两次拟合应得到：**同一条 tonemap、两个不同的 gain**。
   这比"不受光测试"更强，因为它把"引擎固有"与"场景光照"真正分开了。
4. 若将来要做真·不受光验证：走 `original` 模板 + `EmissiveColor` 槽，
   但需新建材质条目（结构性改动，须重做类型表计数与对齐校验）。

## 5. 原文里值得留档的硬事实

- ID Mask 必须导出为 **BC7 sRGB DX11+ / DX10 头 / Extract From Atlas / 关闭预乘 alpha**。
- LUT 存 `.EXR` 或 `.DDS`，因为**值可以是负数或大于 1**（普通图片格式存不下）。
- LUT 版面：**23 列 × 8 行**；披风 LUT 是**16 列 × 5 行**（行 = RGBA 掩码的四种颜色 + 内衬）。
- 材质纹理槽序（SDK "Armor LUT" 预设）：第 1 = decal/颜色图集，第 4 = 法线，第 8（倒数第 4）= ID Mask 数组。
- UVMap 分工：`.000` = ID Mask/Pattern/法线；`.001` = bump 贴图；`.002` = decal。
- 披风由"RGBA 掩码 + 披风 LUT + 图标图集 + 渐变图"四件套决定，**RGBA 掩码的 alpha 还决定披风长度**。
