# Cross-Armor Planner Decision Tree

本文件是替换护甲规划器的目标选择规范。它用于约束后续实现和重构，避免规划器退回到“先绑定来源、再局部补救”的行为。

## 适用范围

- 头部和身体部位的自动目标选择。
- Slim、Stocky、Any 三种身形的候选选择。
- 同一物理 Unit 被多个 archive 共享时的候选复用。

本文件只规定第一阶段的目标候选选择。来源 Unit 的最终绑定必须在所有目标 archive 完成候选选择、并完成全局身形策略分析后进行。

## 基本术语

- `逻辑部位`：至少由 `PartKind + Layer` 组成；如果同一组合仍包含不同实体，应继续使用语义族区分。
- `物理目标`：一个目标 Unit AssetKey。多个 archive 可以引用同一个物理目标，但最终只能生成一份输出。
- `双身形`：同一逻辑部位中同时存在 Slim 和 Stocky 两个候选。
- `Any`：目标部位不区分身形的候选。
- `最大`：优先比较存储尺寸；尺寸相同则使用稳定的 AssetKey 顺序作为决胜规则。

## 头部规则

头部不参与身体身形决策。

每个目标 archive 直接选择该 archive 中尺寸最大的可见 Head Unit，且每个 archive 只选择一个 Head Unit。

## 身体部位决策树

对每个目标 archive、每个逻辑部位独立执行以下决策树：

```text
同层级是否存在完整双身形？
  是 -> 选择同层级最大的 Slim 和最大的 Stocky
       结束本逻辑部位

  否 -> 同层级是否存在 Any？
          是 -> 选择同层级最大的 Any
               结束本逻辑部位

          否 -> 其他层级是否存在完整双身形？
                  是 -> 选择其他层级最大的 Slim 和最大的 Stocky
                       结束本逻辑部位

                  否 -> 其他层级是否存在 Any？
                          是 -> 选择其他层级最大的 Any
                               结束本逻辑部位

                          否 -> 标记为待最终兜底
```

其中，“最大的 Slim 和最大的 Stocky”是分别在各自身形候选组内选择最大者，不是从所有候选中简单取两个最大 Unit。

## 选择约束

第一阶段只选择目标候选，不绑定来源 Unit，也不决定最终来源身形。

同一逻辑部位的自动候选数量限制如下：

- 双身形命中：最多两个目标，分别为 Slim 和 Stocky。
- Any 命中：只能有一个 Any 目标。
- 待最终兜底：最多选择最大的两个不同具体身形目标。
- 不得因为同一部位存在多个层级、多个语义名称或多个共享引用而额外增加可见候选。

如果一个物理目标已经被其他 archive 选择：

- 该物理目标已经是 Any：当前 archive 复用 Any 结果。
- 该物理目标已经属于 Slim + Stocky 配对：当前 archive 复用这对结果。
- 该物理目标当前只有一个具体身形：优先在同层级补齐另一个身形，其次在其他层级补齐。
- 不得再次添加第三个同逻辑部位的可见目标。

## 来源身形的后续决议

所有目标 archive 的候选都完成后，才能执行来源身形决议：

```text
全部 archive 候选完成
  -> 收集 Target=Any 且来源没有真实 Any 的部位
  -> 标记需要优先身形决议的 archive
  -> 分析共享物理目标产生的身形传播
  -> 确定每个 archive 的直连、优先或反向策略
  -> 绑定具体来源 Unit
  -> 执行最终兜底
  -> 执行计划一致性校验
```

来源只有一个 Slim 或只有一个 Stocky 时，可以将其作为有效 Any 参与补全判断，但不得丢失其真实身形信息。真实 Any 与“只有一个具体身形的有效 Any”必须在计划诊断中区分。

## 共享物理目标

一个物理目标只能有一个最终来源绑定。如果优先身形 archive 使共享目标形成反向绑定，其他引用该物理目标的 archive 必须整体采用相同的反向策略：

```text
正常策略：Target Slim   -> Source Slim
          Target Stocky -> Source Stocky

反向策略：Target Slim   -> Source Stocky
          Target Stocky -> Source Slim
```

反向策略必须作用于整个 archive 的身体候选，不能只作用于共享的单个胸部、手臂或胯部。一个 archive 不得同时出现直连和反向两种具体身形策略。

如果共享关系要求一个 archive 同时使用两种互相冲突的策略，规划器必须报告计划冲突，不得静默采用先处理的 archive 结果。

## 最终校验

写出计划前必须拒绝以下结果：

- `Target=Stocky` 绑定 `Source=Slim`，且当前 archive 没有明确的整体反向策略。
- `Target=Slim` 绑定 `Source=Stocky`，且当前 archive 没有明确的整体反向策略。
- 同一逻辑部位超过一个 Any，或超过一对 Slim + Stocky。
- 同一逻辑部位出现第三个自动命中的目标 Unit。
- 同一 archive 的不同身体部位在没有明确反向策略时出现不同来源身形。
- 同一物理目标被分配多个不同来源 Unit。

计划诊断应输出每个物理目标的目标身形、来源身形、逻辑部位、层级、语义族、所属 archive、共享 archive、选择阶段和最终身形策略，确保可以独立审计完整预测表。
