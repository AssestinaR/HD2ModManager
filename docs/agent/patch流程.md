1. **源 patch 分析阶段**

- 扫描 patch 文件组，识别被替换的游戏内对象。
- 建立“对象 -> 相关 Unit -> 有效模型部件 -> 材质/贴图”的来源索引。
- 剔除隐藏模型、极小模型、占位模型。
- 只提取模型和贴图，不继承源骨架、不继承源 Unit 壳。
- 记录每个有效模型属于哪个部位，这是后续注入的核心元数据。
2. **目标资产提取阶段**

- 输入必须是对象集，而不是单个对象。
- 从当前游戏资产中提取该对象集覆盖到的全部 Unit。
- 对共享 Unit 去重。
- 检测这些 Unit 是否还被其它未选择对象共用，并返回风险信息。
- 所有目标 Unit 壳必须来自当前游戏资产，缺失时应报错，不允许旧版兜底。
3. **目标 Unit 最小化阶段**

- 每个目标 Unit 只保留壳、必要引用、注入所需结构。
- 删除原版可见模型，避免原版模型和注入模型混杂。
- 保留必要 Composite/Bone/StateMachine 引用方式要按 SDK/autofix 对齐。
4. **注入阶段**

- 按“部位”把源 patch 的有效模型/材质/贴图注入到目标 Unit 集合。
- 同一身体部件被多个物品共享时，只输出一次对应 Unit。
- 骨骼应使用当前目标/SDK avatar 绑定链路重建，不从源 patch 继承。
5. **封装链路**

- `Adaptation` 应该提供一个“一键重构 patch”的高级 API。
- 后置程序只提供：源 patch 文件组、目标对象集或重构策略、输出路径。
- 内部再串起分析、目标提取、最小化、注入、骨骼附加、写包。
- 同时保留每个阶段作为独立工具，便于诊断和单测。

> ⛔ 已过时（2026-11-08）：现行链路里**没有**"源 patch 一步产出可部署 patch"的 API。转换（CLI `vpk2patch`；
> 老库里叫 `vpk2patch/` 的基底目录由 `ModContentLayoutMigration` 一次性改名成 `sectional/`）只产出 `sectional/`；
> 生效层 `Overwrite/` 只由编译基座（`ModCompileService.CompileAsync`）
> 从 `sectional/` + 条件（目标护甲 / section 开关 / 材质开关）算出，部署段再把它写进游戏
> （见 [`sectional-compile-base-20261108.md`](sectional-compile-base-20261108.md) §1）。上面第 1–4 阶段的
> 提取/最小化/注入语义仍然有效，但"分析…注入…写包"这一串要停在 `sectional/`。
