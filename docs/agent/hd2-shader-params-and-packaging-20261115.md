# 参数强度表 + 打包架构建议（2026-11-15）

> 前半：当前成品（`famA_product3`）里每个能力的**实际强度**与调整方式，全部按**线性值**给，
> 因为屏幕上是 `sRGB = pow(linear, 1/2.2)`，看屏幕调会一直调不准（我们连着踩了两版）。
> 后半：后续 mod 该"每个内置一份专用着色器"还是"通用着色器 + 各自贴图"。

## 1. 当前成品的实测强度

贴图：`G/B = 30/255 = 0.118`（底色）、`A = 90..190`、孔洞 6.7%、`R = 255 保留`

| 能力 | 参数 | 当前值 | 线性贡献 | 屏幕上 |
|---|---|---|---|---|
| **底色/受光** | `BASE_TINT` × `AMBIENT` × `EXPOSURE` | 1.0 / 0.30 / 0.20 | 0.007（背光）~ 0.024（受光） | 0.11 ~ 0.18，暗 |
| **半透明** | 贴图 A × 呼吸 | 0.353~0.745 | 与呼吸相乘 → **0.12 ~ 0.75** | 透过率 25% ~ 88% |
| **镂空** | `CUT_THRESH` | 0.50 | 二值 | 孔洞比例**由贴图定**，当前 6.7% |
| **金属高光** | `METAL_K` / `GLOSS` | 0.10 / 60 | 峰值 **0.020** | 比底色多 0.17 灰阶，窄条 |
| **边缘反光** | `RIM_K` | 0.02 | 峰值 0.004 | 几乎不可见 |
| **自发光** | `EMIS_PULSE` | 0.10 | 峰值 **0.0024** | +0.06 灰阶，**很弱** |
| **动态** | `PULSE_RATE` | 2.0 弧度/秒 | — | 周期 **3.14 秒** |
| **动态幅度** | `ALPHA_PULSE_MIN` | 0.35 | — | alpha 在 **35%↔100%** 摆动 |

> 注意：现在肉眼看到的"发光感"主要来自**金属高光 + 呼吸**，不是 `EMIS_PULSE`（它只有 0.0024）。
> 想要"真的在发光"，把 `EMIS_PULSE` 提到 0.5~2.0。

## 2. 每个参数怎么调（含极端后果）

| 参数 | 当前 | 建议范围 | 调大 | 调小 | 极端后果 |
|---|---|---|---|---|---|
| `EXPOSURE` | 0.20 | 0.10 ~ 0.35 | 变亮，>0.5 开始发白/乳白 | 变暗 | >0.8 全白；<0.05 全黑 |
| `CUT_THRESH` | 0.50 | 0.30 ~ 0.70 | 孔变大变多 | 孔变小变少 | >0.9 整片被丢；<0.1 一个孔都没有 |
| `BASE_TINT` | 1.00 | 0.3 ~ 1.0 | 底色更实 | 更暗 | 无所谓，它会和 EXPOSURE 相乘 |
| `AMBIENT` | 0.30 | 0.1 ~ 0.6 | 背光面也亮，扁平 | 明暗对比强 | >0.8 像自发光；0 背光全黑 |
| `METAL_K` | 0.10 | 0.05 ~ 0.40 | 高光更亮 | 更弱 | >0.6 又是"乳白/整片反光" |
| `GLOSS` | 60 | 20 ~ 200 | 高光收成点 | 铺开成大片 | >300 几乎没有高光；<10 整个曲面都亮 |
| `RIM_K` | 0.02 | 0 ~ 0.10 | 边缘亮圈 | 无 | >0.2 边缘糊成白边 |
| `EMIS_PULSE` | 0.10 | 0 ~ 2.0 | 明显自发光 | 关掉 | >3 过曝，且会盖掉其余所有细节 |
| `PULSE_RATE` | 2.0 | 0.5 ~ 8.0 | 呼吸更快 | 更慢 | >20 频闪；<0.3 像静止 |
| `ALPHA_PULSE_MIN` | 0.35 | 0.05 ~ 0.8 | 呼吸不明显 | 呼吸更狠 | 0 = 周期里会完全消失一下 |
| 贴图 `A` 上下限 | 90..190 | 20 ~ 255 | 整体更实 | 更透 | 255 = 不透明；0 = 全透（看不见） |
| 贴图 `G/B` | 30 | 0 ~ 200 | 底色变亮 | 更黑 | >120 再加 EXPOSURE 必然乳白 |
| 贴图孔洞比例 | 6.7% | 2% ~ 30% | 更破 | 更完整 | >50% 结构会散（`--pitch/--radius` 控制） |

### 调参顺序（照这个顺序，别乱）

1. **先定 `EXPOSURE` 和贴图 `G/B`** —— 让主体是想要的那个黑。这一步没定，后面全白调。
2. **再定贴图 `A` 的上下限** —— 决定"最实/最透"。呼吸是乘在它上面的。
3. **再定 `METAL_K` / `GLOSS`** —— 从 0.10 起步往上加，加到刚好出现一条窄高光就停。
4. **最后定动态**：`ALPHA_PULSE_MIN`（幅度）→ `PULSE_RATE`（快慢）。
5. 要真发光才动 `EMIS_PULSE`，**从 0.1 起步，每档翻倍试**（因为它很容易盖掉一切）。

## 3. 打包架构：专用着色器 还是 通用着色器 + 贴图？

### 3.1 先说一个硬约束

我们改的这条 3 RT 光照 pass 属于**某一条材质载荷**，而载荷属于**某一条材质**。
同一个材质 id 只能有一份载荷 —— **两个 mod 同时覆盖同一个根材质，后装的会把先装的整个盖掉**。

所以"每个 mod 各带一份专用着色器"这件事，**只在前缀是"该 mod 自带根材质"时才成立**：

| 路线 | 形态 | 已被实机证明 |
|---|---|---|
| **A 专用** | mod 自己造一条**根材质**（`parent=0`）并自带载荷，子材质 parent 指向它 | ✅ Milfy CE-07 就是这个形态：`0xe577db2cf97fcddc`，`parent=0`，`undat2=gpuSize=4,037,328`，4 MB 载荷 |
| **B 通用** | 一份"着色器库"覆盖**本体根材质**（`0xef9b3fc2` / `0xd84d0463`），各外观 mod 只带**贴图 + 子材质** | ⚠️ 形态尚未实机验证（探针包 `E:\tmp\hd2-p73-rainbow` 就是为验证它做的） |

### 3.2 对比

| | A 专用（每 mod 自带根） | B 通用（共享库覆盖本体根） |
|---|---|---|
| 多 mod 共存 | ✅ 各有各的根，互不干扰 | ⚠️ 只有一个库能生效，别人再覆盖本体根就打架 |
| 维护 | ❌ 修一个 bug 要改 N 份 | ✅ 只改一处 |
| 体积 | ❌ 每 mod 多 4 MB 载荷（8 条 × 52 KB SHEX + 200 条原版记录） | ✅ 外观 mod 只多一张贴图 |
| 参数自由度 | ✅ 每个 mod 参数随便写死 | ❌ 参数全局统一，除非用贴图编码预设 |
| 与本体更新 | ✅ 不依赖本体根的结构 | ❌ 本体换版本、根载荷变化，库就得重做 |
| 已证明 | ✅ 实机 | ⚠️ 待验证（§3.1） |

### 3.3 我的建议：**B 为主，A 当逃生舱**

```
【共享库】hd2-shader-lib（一个 mod）
    覆盖 0xef9b3fc2fc1ba61e 的载荷（11 槽，advanced 族）
    覆盖 0xd84d04634a1e2f60 的载荷（3 槽）
    内含：通用着色器 + 若干参数预设

【外观 mod】每个只带
    自己的贴图（4096² BC7，R/G,B/A 四通道：镂空/底色/透明度）
    自己的子材质（RoughnessMap 槽指向自己的贴图）
    ❌ 不带任何着色器
```

理由：

1. **多 mod 共存是刚需**。我们已经知道同一个 bundle 里 Milfy、MourningVeil、HF 数据全在
   `9ba626afa44a3aa3` 上叠 `patch_N`。如果每个外观 mod 都自带根载荷，只有最后装的那个能生效。
2. **参数差异其实大多能落到贴图里**：底色浓淡（G/B）、透明度（A）、镂空形状（R）、
   花纹细节（G/B 里画）—— 这些正是"每 mod 不同"的部分。
3. **只有"完全不同着色逻辑"才需要 A**：比如宝石要折射、要各向异性高光、要走另一套 BRDF。
   那时自造根材质，代价是 4 MB 和独立性。

### 3.4 如果 B 要多套参数，就用贴图编码预设（未验证）

光照 pass 里**没有材质变量 cbuffer**，所以"每材质不同参数"只能从贴图里读。
可行做法：`R` 通道的"保留电平"本来就是自由的（只要 ≥ `CUT_THRESH`），可以拿它编码预设号：

```hlsl
// 贴图里：孔=0.0，预设 0 的保留区=1.00，预设 1=0.90，预设 2=0.80 …
float keep = s.r;
int   preset = clamp((int)floor((keep - 0.5) / 0.1), 0, 4);
```

然后 `switch(preset)` 选一组常量。**风险：BC7 压缩会抖动电平**，所以每档要留 0.1 的间距，
且要在实机上确认 `keep` 落在正确档位。这条我们**没有验证过**，只作为设计方向。

## 4. 一句话结论

- **参数**：一切按线性值算，`EXPOSURE` 定生死；顺序是 曝光/底色 → 透明区间 → 金属 → 动态。
- **打包**：默认走 **B（一份共享着色器库 + 每个外观 mod 只带贴图）**，因为多 mod 共存和可维护性都压倒性；
  只有需要完全不同的着色逻辑（宝石折射那类）才回到 **A（自造根材质 + 自带载荷）**。
- **B 的前提**是先验证"覆盖本体根材质能不能画" —— 探针包 `E:\tmp\hd2-p73-rainbow` 就是干这个的，
  跑一次就知道。
