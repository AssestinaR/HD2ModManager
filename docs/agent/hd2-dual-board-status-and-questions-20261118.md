- 板面中央出现过一块**三角形区域**，颜色比周围亮、不随呼吸变化

## 3. 已用证据确认的事实

| 事实 | 证据 |
|---|---|
| famA 的 60,504 pass 可以注入自定义 PS 并生效 | 网孔/半透明/时间呼吸实机可见；记录 `ISGN 252 / OSGN 92 / 60,504 B`，fxc 反汇编无异常 |
| **顶点权重清零 + 骨骼组保留 = 静止且能启动** | 用户实机观察（角色做夸张动作，板子不动） |
| **删除骨骼组（`boneInfoOffset=0`）= 启动崩溃** | 日志原文：`Access violation (0xc0000005) accessing address 000000000000000C`，`Error context: package #ID[9ba626afa44a3aa3] / unit #ID[02e8377209ba0008]`，发生在 `PackageLoader` 阶段 |
| 材质缺失时引擎用品红渲染，且该区域不参与材质动画 | 观察 + 品红区域不随呼吸变化 |
| 引擎按 **mesh 的材质槽键** 去单位材质表查材质 | 解析出的结构：mesh 材质槽 `[0x348bb73b, 0x348bb73c]`，单位材质表三条 slotKey 全是 `0x348bb73b` |

## 4. 未解问题（希望专家定向）

### Q1 双 section 的正确构建方式是什么？

现状：同一 mesh 内两个 section，各带不同的 `MaterialSlotId`；布局编译器生成的单位材质表有 3 条，但三条 slotKey 相同（`0x348bb73b`），而 mesh 用到两个不同的键（`…3b` / `…3c`）。

**问题**：单位材质表的 slotKey 语义是什么？是"每个 section 一个键"，还是"每个 mesh 一个键"？三维引擎通常怎么做？

### Q2 为什么只改一个 u32 会让整个 unit 不渲染？

最近一次实验：只把材质表 `[1]` 的 slotKey 从 `0x348bb73b` 改成 `0x348bb73c`（其余一律未动，侧车哈希不变），结果**两块板全部消失**。

**问题**：这个字段是否参与某种校验（哈希/一致性），或者 slotKey 必须是**颜色/材质槽的注册表项**而不是自由值？

### Q3 "静止但不崩"的合法表达只有零权重吗？

- 删骨骼组 → 崩（已证）
- 权重清零 + 骨骼组保留 → 静止且不崩（已证）

**问题**：引擎对"所有顶点权重为 0"的网格是如何处理的？是否需要显式的"静态网格"标志（而非零权重这种旁路做法）？

### Q4 有没有更规范的多材质做法？

替代方案候选：
1. 同一 unit 内**多个 mesh**（而不是多个 section）
2. 复合资源（composite / 多 unit 拼接）
3. 两个独立 unit + 素体注册（试过：注册 slot 8 会让游戏启动崩溃）

**问题**：哪种是引擎推荐的？素体的 slot 8/9 是否允许挂自定义 unit？

### Q5 渲染层级与描边

半透明族（`e577db2c`）**不写深度**：舰内全息地球仪会盖在板子上。要做动漫描边，需要"写深度"的不透明路径。

**问题**：HD2 的描边常规做法是反向外壳（多一层放大网格 + 正面剔除），还是靠后处理（法线/深度边缘检测）？
