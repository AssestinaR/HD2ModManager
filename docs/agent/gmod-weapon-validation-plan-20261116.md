## 0. 本轮新增的关键事实（改变了实验设计）

1. **HD2 有数据驱动的「动画事件 → 效果」表** [F]：filediver 的 `datalibrary/animation_event_trigger_settings.go` 解析 `generated_animation_event_trigger_settings.dl_bin`，每条是 `实体路径 → [动画事件 → 音效 / 效果(粒子) / 镜头震动 / 可见性组 / 节点缩放]`。
   → 武器开火的枪口效果**很可能**就挂在这里 [I]。如果属实，「粒子是否共享」「开火对应哪个动画事件」都能**离线**回答。
2. **写过的 `.dl_bin` 会让游戏闪退**（2026-11-11 起，护甲注册表实测）[F，`dl-bin-write-freeze-20261111.md`]。
   → 如果粒子引用确实只存在于上述 `.dl_bin` 里，「改引用让只有目标武器指向新粒子」这条纯资源路线**大概率被堵死** [I]。粒子独立性因此是头号问题。
3. **HD2SDK-CommunityEdition 有动画与粒子的序列化代码** [F]：`stingray/animation.py`（含 `save()` 与位置/旋转/缩放压缩）、`stingray/particle.py`（读写对称的 `Serialize`）、`stingray/state_machine.py`（`save()`）。
   → 之前写的「HD2 动画不能写回」「粒子不能从零创建」应改为「**已调查的工具尚未证明**」。该仓库**无许可证文件**（GitHub API `license: null`），只能参考格式知识，不能移植代码。
4. **SourceIO 的 Source 1 动画解码已核实** [F，`library/models/mdl/structs/local_animation.py`，最近提交 2026-10-07]：支持 `RAW_ROT`(Quaternion48)、`ANIM_RAW_ROT2`(Quaternion64)、`ANIM_ROT/ANIM_POS`（RLE 压缩值）、分段（section）、外部 `.ani` 块与块表、`FRAMEANIM`、delta 标记；`ikrule_*`、`zero_frame_*` 字段读入，但**没有找到应用 IK 规则的代码**。MIT 许可，核心约 400 行 Python，可移植。

## 1. 实验总览与顺序

| # | 实验 | 在哪做 | 侵入性 | 回答的问题 | 依赖 |
|---|---|---|---|---|---|
| V0 | AR-23 资源结构普查 | 离线（filediver 只读导出） | 无 | Unit/骨骼/挂点/材质/动画/状态机/效果引用 | — |
| V1 | 粒子引用位置与共享度 | 离线（同上 + 触发表导出） | 无 | 枪口粒子引用在哪、被几把武器共享 | V0 |

| V3 | 开火/换弹事件只读探针 | **游戏内**，Lua 只读 | 低（只记日志） | Lua 能否可靠观测开火/换弹并归属到武器实例 | V0 |
| V4 | 粒子独立性实机验证 | 游戏内，资源 patch | 低（可删 patch 回退） | 改后是否只影响目标武器 | V1, V2 |

## 2. 各实验细则

### V0 AR-23 资源结构普查（离线）

- **做法**：filediver 导出 AR-23 的武器实体：Unit（含 mesh / LOD / 材质槽）、骨骼树、`state_machine`、动画列表（带开关导出）、prefab；`generated_weapon_customization_settings` 里与它相关的定制件（瞄具、弹匣、涂装）。同时确认**第一人称与第三人称是否同一 Unit**。
- **产出**：`docs/agent/` 下一份结构表：实体 → Unit → mesh/材质/骨骼；状态机 → 动画 → 被驱动的骨；定制件挂在哪些节点。
- **可观察的成功标准**：
  - 能列出 AR-23 Unit 的全部骨骼名（或哈希）及父子关系；
  - 能指出弹匣、枪栓、扳机（若存在）分别是哪根骨，且该骨在换弹 / 开火动画里有非零运动；
  - 能指出第一人称显示用的是哪个 Unit。
- **失败退出**：filediver 无法导出武器 Unit 或动画 → 改用 HD2SDK-CE 在 Blender 中导入同一资源再试；仍失败 → 停在此处，报告「武器 Unit 结构未知」，后续全部暂停。

### V1 枪口粒子的引用位置与共享度（离线）

- **做法**：用 filediver 的 `animation-event-trigger-settings-json-dumper` 导出触发表；找到 AR-23 实体的条目里带 `effect` 的动画事件；统计同一粒子资源被多少个实体引用。若触发表里没有枪口效果，再查 V0 中 Unit / 武器设置里的其他引用。
- **产出**：「AR-23 开火 → 动画事件名 → 粒子资源路径」链；该粒子的引用计数与引用方列表；**引用存放在哪类文件里**（`.dl_bin` / Unit / 其他）。
- **可观察的成功标准**：链条每一环都有导出数据支撑，不靠猜。
- **分支结论**（不需要进游戏就能下）：

| V1 结果 | 粒子路线结论 |
|---|---|
| 引用在 Unit 或其他可 patch 的资源里，且只有目标武器使用 | 资源路线可行，进 V4 |
| 引用在可 patch 的资源里，但多把武器共用 | 克隆粒子 → 只改目标武器那份引用；进 V4 |
| 引用**只**在 `.dl_bin` 里 | 资源路线按 2026-11-11 结论**不可行**；粒子默认降级为「保持 HD2 原生」，Lua 路线见 V3/V4 备注 |

### V2 HD2 格式往返测试（离线）

- **做法**：对 V0/V1 涉及的 `.particles`、`.animation`、`.state_machine`、武器 Unit，按 HD2SDK-CE / hd2-particle-modder 公开的结构自己写只读解析与原样写回（在**临时实验目录**，不进仓库代码），比较字节。
- **可观察的成功标准**：原样写回与原文件**字节完全一致**；改一个已知字段（如粒子寿命）后，重新解析只有该字段变化。
- **失败退出**：某格式无法字节一致 → 该格式只允许「改已有字段」，不允许增删结构；在兼容报告里标为「受限」。

### V3 开火 / 换弹事件只读探针（游戏内）

- **前提**：用户确认后执行；使用已有的合规加载路径（不绑定特定加载器）；**只读**，不写任何骨骼、不生成粒子。
- **做法**：
  1. 用 `World.units_by_resource(world, <V0 得到的武器 Unit 路径>)` 列出场上该武器实例（与物理骨运行时找 avatar 的方式相同 [F]）。
  2. 能力探测：`Unit.has_animation_event`、`Unit.animation_event`、`World.animation_event_stream_get`、`Unit.animation_get_state` 是否为函数（`rawget` + `type`，不调用）。
  3. 对每个实例，逐帧读取上述可用接口，把「帧号、时间、实例、事件名或状态」写日志（沿用物理骨的日志预算与轮转）。
  4. 每帧先 `Unit.alive`，不缓存句柄（AV 防护 [F]）。
- **测试脚本**（人工）：单人局，打满一个弹匣（≥ 30 发）、换弹 3 次、切枪 3 次；再在 4 人局重复一次。
- **可观察的成功标准**：
  - 开火：≥ 95% 的射击在同一帧或下一帧有对应记录，空枪 / 切枪时 0 误报；
  - 换弹：每次换弹有可与开火区分的独立记录；
  - 归属：多人局里，能把事件归属到正确的武器实例（不会把队友开火算到自己枪上）；
  - 稳定：整个测试过程无崩溃，日志无错误。
- **失败退出**：没有任何接口能观测到开火 → Lua 粒子补强与 Lua 动画（A2）只能做「常驻 / 与开火无关」的效果，或放弃；只观测到本地玩家 → 只支持本地玩家，报告标注。

### V4 粒子独立性实机验证（游戏内）

- **只在 V1 判定资源路线可行时执行。**
- **做法**：克隆目标粒子为新资源，**只改颜色**（最易肉眼判断）；按 V1 的结论只让目标武器引用新粒子；打成独立 patch。
- **可观察的成功标准**：
  - 目标武器开火时枪口颜色明显改变；
  - V1 列出的所有共享原粒子的武器（至少抽 3 把）开火时**颜色不变**（截图对比）；
  - 删掉 patch 后一切恢复原样。
- **失败退出**：任何一把非目标武器受影响 → 按用户决定（默认禁止污染）判定资源粒子不可用，粒子降级为 HD2 原生。
- **关于 Lua 粒子（备注）**：即使 V3 成功，`World.create_particles` 也只能**额外叠加**一个粒子，**去不掉** HD2 原生枪口火焰；而且要能生成的粒子必须是已打包进游戏资源的 HD2 粒子 —— 它不能直接播放 PCF。所以 Lua 粒子只是「补强」，不能替代 V4。

### V5 SourceIO 动画解码对照（离线）

- **做法**：选 1 把带换弹动作的 GMod v49 武器；在隔离的临时目录用 SourceIO 解码其 sequence；同一模型用 Crowbar 反编译出 SMD；逐帧比较骨骼局部变换。
- **可观察的成功标准**：所有骨、所有帧的位置误差 < 1e-3、旋转误差 < 0.1°；delta 动画单独标注。
- **失败退出**：系统性偏差 → 记录差异类型，决定以哪个为准（以游戏内 GMod 实际表现为最终依据）；无法解释 → 动画路线 A2 暂缓。
- 说明：只读 SourceIO 代码，在临时目录用 `python -I` 运行，不进仓库；移植决定等对照通过后再做。

### V6 模型最小样本（路线 M，游戏内）

- **做法**：1 把结构简单的 GMod `c_` 步枪：剥离手臂 → 部件刚性绑到 V0 找到的 AR-23 同功能骨 → 以 AR-23 Unit 为模板替换 mesh 与材质 → 独立 patch。用现有项目代码做，**不建新仓库**。
- **可观察的成功标准**：第一 / 第三人称都显示新枪；持握无明显偏移；换弹时弹匣跟随 HD2 原生动画运动；其他武器不受影响；删除 patch 后恢复。
- **失败退出**：同调研报告路线 M。

## 3. Lua 能力层：四个维度（采纳 GPT 审核意见）

启动探测只回答第一个问题，降级需要四个维度同时成立：

| 维度 | 问题 | 怎么判断 | 判断时机 |
|---|---|---|---|
| D1 存在 | API 在不在 | `type(rawget(S.X, "fn")) == "function"` | 启动一次 |
| D2 时机 | 当前游戏状态允许调用吗 | 世界已就绪、非加载界面（`update` 连续运行）、本地玩家已找到 | 每帧 |
| D3 对象 | Unit / World 句柄仍有效吗 | 每帧 `Unit.alive`；不缓存句柄；场景图变化看 `num_scene_graph_items` [F] | 每次调用前 |
| D4 验证 | 这个功能在真实场景验证过吗 | 产物声明里的 `verified` 清单（由 V3/V4 等实验结果写入）；未验证的功能默认关闭，需用户手动开启「实验功能」 | 转换期写入，运行期只读 |

- 功能启用条件 = 所需 API 全部 D1 通过 ∧ D4 已验证；每次调用前再过 D2、D3。
- 运行期熔断保留：`pcall` 失败累计到阈值 → 本局关闭该功能。
- D2/D3 是为了**在调用之前**避开 AV，因为 AV 用 `pcall` 拦不住 [F]。

## 4. 不做的事

- 不改任何 `.dl_bin`（2026-11-11 起写入即闪退 [F]，且属于共享数据）。
- 不改伤害、弹药、射速等玩法数据。
- 不使用白名单外的 API，不使用 FFI 写内存。
- 不在验证期建独立仓库、不复制代码、不实现通用转换器。
