# 军械库崩溃测试

把整个 `Armor-Diagnostics` 文件夹放到你的管理器目录中，双击文件夹里的
`Start.cmd`。不要只复制 `Start.cmd`。

## 准备

1. 先在管理器中应用平时会崩溃的映射，随后关闭管理器和游戏。
2. 测试期间不要再打开管理器、换装备、换身形、换头盔或修改 Mod。
3. 双击 `Start.cmd`，之后**只照窗口里的当前提示操作**。游戏会由工具通过 Steam 启动。

## 向导步骤

工具会自动安排 **六组**测试，每组单独启动一次游戏：

1. 不开映射，打开和关闭军械库。
2. 开着映射，打开和关闭军械库。
3. 先不开映射，在军械库**外**按 `F8` 开映射，再试军械库。
4. 先开着映射，在军械库**外**按 `F8` 关映射，再试军械库。
5. 先不开映射，**打开军械库**后按 `F8` 开映射，再试关闭和重新打开。
6. 先开着映射，**打开军械库**后按 `F8` 关映射，再试关闭和重新打开。

**每做完一个提示动作，回工具窗口作答：**

- 正常：直接按回车。
- 打开军械库时崩溃：输入 `O` 后回车。
- 关闭军械库时崩溃：输入 `C` 后回车。
- 其他时刻崩溃：输入 `B` 后回车。
- 卡死：输入 `H` 后回车。
- 只有决定停止**整轮**测试才输入 `Q`。等待游戏里的 `F8` 时可按 `F9` 停止整轮。

每组正常时需要完成三次打开、关闭军械库。某组崩溃或卡死后，
**不重复该组，但还要继续下一组**。不要因为一次崩溃就关闭诊断窗口。
工具会先检查 Lua 是否真的完成切换，未完成不会要求继续测试。

**每组结束都要彻底退出游戏。**崩溃后游戏窗口消失不代表进程结束；
到 Steam 点击“停止”，等 Steam 不再显示“运行中”。工具确认进程结束后
才会启动下一组。不能结束时不要关闭电脑或删掉诊断文件；
稍后重新运行工具会优先恢复原来的设置。

六组结束后，工具恢复原映射并输出一个 ZIP 文件；**只发送这个 ZIP**。
想对比不同映射数量时，完成整轮后再回管理器更改，并另跑一整轮。

本工具不会要求你识别或手工排除“胸部 type3”。它是部件记录的内部类型编号，
不是“第三个胸部 Unit”；目前不能据此认定崩溃原因。

## 数据与限制

ZIP 仅含数字 Item/Unit ID、部件结构、Patch TOC 哈希和长度、时间线、
进程与 Lua 状态及脱敏 Windows 事件。不包含模型包、完整日志、内存转储、
管理器设置、源 JSON 或原始协议。不要发送整个 `data/diagnostics/armor`
目录，其中保存了本机恢复所需的完整备份。

实验仅切换运行时协议，不会重新编译注册表或修改部署。关闭映射只恢复
注册索引，不能撤销已经创建的玩家或军械库预览实例。因此冷启动关闭组
和运行中关闭组应分别解读，单次成功也不代表故障已被修复。
诊断程序自包含 .NET 10；无需用户安装 .NET SDK、Python 或 PowerShell 7。
