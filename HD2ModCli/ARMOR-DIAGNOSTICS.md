# 护甲映射故障诊断（基础版）

在已配置好的管理器目录双击 `Armor-Diagnostics.cmd`。
如果使用单独的诊断附件，请把整个 `Armor-Diagnostics` 文件夹解压到管理器目录，
再双击里面的 `Start.cmd`。不要只拷贝 EXE。

## 开始前

- 保留平时能复现故障的模型包、映射、身形和头盔，不要换成别人的测试包。
- 先在管理器中部署并应用该配置，然后关闭管理器和游戏。
- 本工具不提供第三方 Lua 注入前置。必须已经有可工作的护甲映射运行时。
- 原始配置必须有启用的实际映射。不会重新编译尚未应用的编辑状态。

## 按提示完成

1. 选择问题护甲。选择仅标记报告，不移除其他原始映射。
2. 确认导出内容和临时改动。原始协议先备份到本机。
3. 原始组：从 Steam 启动，确认运行时握手，进入舰船静置 30 秒；
   然后最多进行 3 次“不换装，只打开/关闭军械库”。
4. 发生崩溃或卡死就按对应选项报告；不得自行重启后接着原会话。
5. 完全退出游戏（包括残留进程），可选择关闭所有映射的对照组。
   模型包、装备和源定义不变。本轮不做槽位扩容或缺资源实验。
6. 完全退出后恢复原始协议。发送向导输出的 `*-report-*.zip`。

如果无法恢复或窗口被关闭：下次运行入口将优先恢复，不会开始新诊断。
新版管理器检测到未完成诊断时也会提示先恢复。旧版管理器没有该启动保护，
因此使用单独附件时务必在恢复前保持旧管理器关闭。
协议被外部修改时工具拒绝覆盖，请保留本机备份并联系支持人员。

## 报告与隐私

ZIP 包含：程序版本、数字 Item/Unit ID、部件和启用结构、Patch TOC 哈希与长度、
实际部署 Unit 集合、操作时间线、PID/启动时间/内存使用、脱敏 Windows 事件。
模型名称和键被替换为报告内别名，绝对路径、用户名和任意日志消息不会导出。
发送前可自行打开 ZIP 检查内容。

不包含：模型包、完整游戏/加载器日志、内存转储、原始协议备份、管理器设置或源 JSON。
不要打包发送整个 `data/diagnostics/armor` 目录；那里有仅供本机恢复的完整备份。

本版不会安装前置、修改游戏资产、附加调试器、采样原生内存或强制刷新模型。
诊断附件复用管理器的私有 .NET 10 运行时（如有），否则使用已安装的 .NET 10。
不需要 Python、PowerShell 7 或额外 SDK。Windows 事件采集使用系统自带的
Windows PowerShell，读取失败会在报告中标记，不会阻止恢复。
状态采样仅每 2 秒读取状态文件与进程元数据，最多每组 1 小时。
静置/开关军械库由用户操作，工具不自动判断视觉正确，也不能保证复现偶发问题。
关闭所有映射同时关闭了全部视觉重定向，因此对照结果不能独立证明槽位数量是根因。
